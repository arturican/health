# План до итогового выпуска дневника здоровья

Цель — выпустить личный онлайн-дневник с уже реализованными восемью разделами
и подтвердить, что записи доступны с компьютера и телефона, данные восстанавливаются,
а выпуск можно проверить и откатить. Новые продуктовые возможности остаются
отдельными решениями. [Обзор приложения](APP_GUIDE.md) · [Идеи на будущее](../IDEAS.md)

План составлен 25.11.2026 на локальном срезе `56783fd`. Рефакторинг T269–T272
закрыт целевыми проверками. Последняя зафиксированная публикация frontend — T265
от 21.10.2026. Последняя описанная установка API — T260. Перед новой доставкой
установленные версии предстоит сверить с фактическими. Изменения T270 и T271
затрагивают frontend, T272 затрагивает API. План включает доставку обоих компонентов.
[Приёмка T265](DEPLOYMENT.md#приёмка-t265) · [Приёмка API T260](DEPLOYMENT.md#приёмка-t260-20102026) · [Рефакторинг](REFACTORING_REVIEW.md)

## Очередь исполнения

| Шаг | Что делаем | Что должно быть на выходе |
|---|---|---|
| 1 · [T274](tasks/T274.md) | Повторяем синтетическое восстановление из зашифрованной копии | Воспроизводимое учение с проверкой записей, байтов файлов, прав доступа и отзыва сессий |
| 2 · [T275](tasks/T275.md) | Оператор проверяет свежую внешнюю копию и проводит восстановление в отдельную БД | Подтверждённые свежесть, SHA256, пригодность ключа и результат закрытого восстановления. Состояние всей истории архивов указано отдельно |
| 3 · [T276](tasks/T276.md) | Согласуем охват оповещений к выпуску | Владелец принял действующий почтовый монитор резервирования. Получение письма подтверждено, пределы покрытия записаны |
| 4 · [T277](tasks/T277.md) | Задаём объём дневника, который должен переноситься через интерфейс | Согласованные размеры, набор записей и вложений, среда испытания и критерии успешного переноса |
| 5 · [T278](tasks/T278.md) | Проверяем экспорт и обратный импорт этого объёма | Отчёт о точном сценарии, сохранности записей и файлов и отказе при превышении лимита |
| 6 · [T279](tasks/T279.md) | Собираем и проверяем кандидат выпуска | Точный SHA, полный локальный check, сборка API, применимые проверки доставки и совместимый порядок обновления |
| 7 · [T280](tasks/T280.md) | Публикуем API отдельным артефактом | SHA256 совпал, готовность API подтверждена, сохранность данных проверена, совместимый откат подготовлен |
| 8 · [T281](tasks/T281.md) | Публикуем frontend через CI из `dev` | Успешные обязательные проверки GitHub Actions и опубликованный SHA в `release.txt` |
| 9 · [T282](tasks/T282.md) | Принимаем итоговый выпуск на сайте | Проверены обе версии, браузерные сценарии, API и свежая копия. Результат и эксплуатационные ограничения записаны в регламент |

Статусы ведутся в [TASKS](../TASKS.md). Выбери карточку и попроси выполнить
её или согласуй диапазон. «Следующая» означает одну доступную задачу.
Каждый шаг завершается отдельным локальным коммитом с результатом и записью
в PROGRESS. Условия выхода проверяются перед переходом дальше.

## Где потребуется решение владельца

- **Восстановление.** Для T275 владелец или назначенный оператор подтверждает
  эксплуатационную проверку, имеет доступ к свежей копии и защищённому ключу.
  Ключ, архив и восстановленные данные остаются в закрытом контуре оператора.
  В Git и в чат попадает сводный результат. Если закрытая проверка недоступна,
  укажите, какое доказательство отсутствует и кто может его предоставить.
  [Порядок восстановления](BACKUPS.md#восстановление)
- **Оповещения.** В T276 владелец принял действующую почту о состоянии
  резервирования. При полном отказе VPS базы данных его монитор остановится.
  Независимый канал отложен. [Решение и порядок реакции](MAIL_MONITOR.md#выбор-канала-в-t276)
- **Ёмкость копии.** В T277 укажи, сколько записей и файлов нужно переносить
  в одном файле. Для исходного ориентира можно взять 90 дней существующего
  синтетического демо. Предельный объём задают отдельно. Если он выходит за
  проверенную границу, согласуй меньший объём с понятным способом восстановления
  или отдельную доработку формата. [Синтетическое демо](../README.md#аккаунты-и-синтетическая-демонстрация) · [Ёмкость копий](BACKUP_CAPACITY.md)
- **Доставка.** Перед T280–T281 требуется явное разрешение на выкладку API,
  push `dev` и публикацию frontend. Закрытые браузерные проверки на сайте
  используют выделенный синтетический аккаунт и согласованный объём действий.
  [Регламент VPS](DEPLOYMENT.md) · [Правила Git](../AGENTS.md)

## Как разблокировать шаг

1. Если тест выявил дефект, запиши ошибку, воспроизведение и затронутые файлы
   в карточку. Создай маленькую задачу с регрессией, выполни её после согласования
   и перепроверь связанный критерий. После изменений кандидата заново пройди
   связанные проверки и все обязательные проверки перед доставкой.
2. Если понадобится новый формат копии, сначала согласуй формат, обратную
   совместимость, граничные условия и миграцию. Затем раздели реализацию
   экспортера, импортера и интерфейса на отдельные задачи. После их выполнения
   вернись к T278. Нынешние защитные лимиты сохраняются до проверенного решения.
3. Если не хватает доступа, внешней копии, канала доставки или решения владельца,
   запиши конкретный блокер в TASKS/PROGRESS и какой результат позволит продолжить.
   Синтетические проверки, эксплуатационные наблюдения и пользовательские
   решения подтверждают разные критерии, отмечай их отдельно.
4. Если публикация остановилась между компонентами, зафиксируй реально
   установленную пару версий. Продолжай по проверенному плану совместимости
   или откати изменённый компонент на известный совместимый релиз по регламенту.
   После исправления снова проверь доступность API и состояние копий.

Таблица предполагает совместимое обновление API перед frontend. Если T279
покажет, что эта пара версий несовместима, согласуй переходный релиз или другой
порядок и поправь зависимости карточек до начала доставки.

## Когда выпуск считаем готовым

- **Дневник.** На компьютере и мобильном работают вход и все восемь основных
  разделов. На синтетическом аккаунте проверены сохранение и перечитывание
  записей, загрузка и скачивание вложений, выход и недоступность приватного API
  без входа. Защищённые данные проверяются в рамках согласованного демо.
- **Данные.** Есть свежая проверенная внешняя копия и отчёт о восстановлении
  в отдельную БД. Записаны возраст снимка, длительность процедуры, подтверждённый
  объём пользовательского экспорта и проверка отказа при его превышении.
- **Эксплуатация.** Записаны подтверждённый охват оповещений по T276,
  ограничения, ответственный и порядок проверки при сбое.
- **Доставка.** Совпадают намеченные версии артефактов, успешный CI и данные
  live-приёмки. Для API записаны SHA256 и версия `current`, для frontend —
  точный `release.txt`. Сохранность данных и совместимый откат подтверждены.
- **Передача работы.** В DEPLOYMENT/PROGRESS есть дата, SHA, CI, результат
  браузерной приёмки, состояние резервной копии, ограничения и ссылка на порядок
  отката. Инструкция пользователя отражает подтверждённые границы копирования.

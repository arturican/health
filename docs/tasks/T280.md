# T280 — Доставка и проверка API

Зависимость [T279](T279.md). Требуются явное разрешение на выкладку API,
живой SSH-доступ, свежая подтверждённая внешняя копия и проверенная совместимость
нового API с тем frontend, который будет работать во время переключения.
Результат — установленный API с точной версией и готовым путём отката.

1. Сверить фактический `current`, активную схему и свежесть внешней копии.
   При необходимости получить новую копию штатной процедурой и подтвердить
   SHA256 на втором VPS до операции. Точная команда и доступ — по регламенту.
2. Собрать или взять артефакт API из SHA T279. Проверить SHA256 перед установкой,
   развернуть в новый каталог релиза, сверить права, состав архива и версии
   зависимостей. Проверить файлы миграций и их контрольные суммы.
3. Применить только согласованные и совместимые миграции, если они есть.
   До изменений схемы выполнить предусмотренные проверки данных и прав доступа.
   Переключить API атомарно по `current` и проверить здоровье, readiness и
   `401` приватного маршрута без входа. Сохранность подтвердить штатным способом,
   записывая только сводные равенства и статусы.
4. При отказе остановить доставку frontend, восстановить известный совместимый
   `current` по регламенту и проверить API. Изменение схемы в обратную сторону
   требует отдельного решения и проверки данных.

Готово, когда SHA артефакта и его SHA256 сверены, `current` указывает на ожидаемый
релиз, API доступен и пройдены применимые проверки данных/прав. Если фактически
развёрнутый артефакт совпал, зафиксировать проверенное совпадение вместо
повторной установки. Результат в DEPLOYMENT и TASKS/PROGRESS, `check:docs`, diff,
один локальный коммит отчёта.

# T252a — Независимый канал оповещений

IMP-021 / AUD-011. Пользователь 21.10.2026 (Europe/Moscow) выбрал:
настроить SMTP на втором VPS для прежнего получателя. Provider monitoring —
проверить доступное окружение, наличие в кабинете пользователю неизвестно.

## Подтверждённый выбор

Frontend159.194.208.200 → самостоятельный Postfix/OpenDKIM → MX прежнего
получателя. Data2.26.54.81 не является relay. SMTP доступен только loopback25;
TLS с проверкой внешнего MX, прежний From no-reply@auth.arturican.com.
Новое имя mail-monitor.arturican.com и отдельный selector healthmonitor2026;
приватный DKIM key создаётся только на frontend. Data key не переносится.

Read-only preflight: frontend Postfix/OpenDKIM не установлены; исходящий TCP25,
EHLO/STARTTLS с валидным сертификатом/QUIT до двух публичных MX прошли.
Публичный DNS через DoH: NS ns1/ns2.mitelis.cc; frontend PTR, новое A и selector
отсутствуют; auth SPF разрешает только data IP. WSL UDP DNS не отвечал,
не использовался как доказательство отсутствия записи; DoH дал явный NXDOMAIN.
Найдены только cloud-init/служебные guest/RAID units; внешнего monitor agent
не обнаружено. Это не доказывает отсутствие мониторинга в кабинете провайдера.
DNS/provider credentials в доступных целевых env/config locations не найдены;
кабинет Play2go не подключён. Его состояние остаётся неподтверждённым.

## Приватность и доставка

Прежний recipient переносится из закрытого data backup-monitor.json только
приватным потоком в root0600 frontend config; не печатать адрес, очередь/сырые
mail logs или секреты. Журналы новых MTA фильтруют адреса до отправки.
SMTP acceptance не является receipt. До DNS/key/loopback/privacy gates —
defer_transports=smtp, без внешних писем и новых monitor timers.
Отказ frontend всё ещё требует внешнего provider monitor вне двух VPS.

Установка и rollback — [T262](T262.md). Watchdog [T253a](T253a.md) и offsite
[T254c](T254c.md) не активируются от одного выбора канала; нужны работающий
SMTP и доказательства доставки. AUD-011 остаётся открытым.

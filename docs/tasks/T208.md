# T208 — Email-мониторинг резервного копирования

Зависимость: T207. Статус — в TASKS.md.

Выбор пользователя 20.10.2026: существующий loopback SMTP, хранение 7/14 без изменений.
Результат: отдельный скрипт использует T206 и сообщает о первом unhealthy,
переходе обратно в healthy; первое healthy не создаёт письма. Дубликаты состояния
подавляются приватным атомарным файлом под flock. Смена получателя начинает
новую историю; адрес в state/логи не записывается. Ошибка SMTP не фиксирует успех.
Доставка как минимум один раз: сбой после принятия DATA или до записи состояния
может повторить письмо, ровно-однократная доставка не обещается.

Диагностический запуск по умолчанию ничего не отправляет/не пишет. --send
включает SMTP на 127.0.0.1, с ограниченным тайм-аутом. Свежий архив при текущем
запуске сервиса — pending без письма/изменения state; устаревший — ошибка.
В письмах только технические статусы, без путей/архивов/данных дневника.
Конфигурация и state закрыты, symlink и некорректный ввод отклоняются.

Файлы: deploy/backup_monitor.py и тесты, BACKUPS, TASKS/PROGRESS.
Бюджет: до 250 строк реализации, стандартная библиотека; без новых зависимостей.
Проверки: синтетические переходы/повторы/сбой SMTP/конкуренция/приватность,
все Python deploy, npm run check, verify_build, docs/diff check.
Настоящие письма, установка на VPS и изменение retention не выполняются.

# T276 — Способ контроля сбоев и резервных копий

Зависимость [T275](T275.md). Результат — согласованный с владельцем охват
оповещений к выпуску. 25.11.2026 владелец выбрал действующий почтовый монитор
резервирования на VPS базы данных. Получение письма подтверждено.
При полном отказе VPS базы данных монитор перестаёт работать. Внешние копии
проверяются штатной командой по необходимости. [Решение владельца](../MAIL_MONITOR.md#выбор-канала-в-t276)

## Варианты при отдельном запросе

1. Сверить факты из BACKUP_CONTROL и MAIL_MONITOR. Объяснить, что монитор на
   сервере БД теряет возможность сообщить при полном отказе этого сервера.
2. Если владелец выбирает ручной контроль, согласовать ответственного, интервалы
   и два способа проверки: доступность health/readiness с другой машины и
   свежесть/целостность offsite. Зафиксировать порядок реакции на сбой и сделать
   один разрешённый контрольный обход. Записать риск задержки обнаружения.
3. Если нужен прежний независимый SMTP, отдельно возобновить T262 при наличии
   доступного способа доставки. После его подтверждения выполнить T253a и T254c
   по их карточкам. Для другого канала сначала согласовать интеграцию и создать
   отдельные карточки. Проверка — синтетические отказ и восстановление, видимое
   получение обоих сообщений, отсутствие повторного спама, проверка таймеров и
   отката. Рабочие API и БД для имитации отказа не останавливать.

## Критерии завершения

Для решения о выпуске нужны подтверждение получения письма, согласие
владельца на действующий охват и запись эксплуатационного ограничения.
Отдельные задачи независимого контроля ведутся по своим критериям.
Проверки документации и diff, запись в TASKS/PROGRESS и локальный коммит.

# T260 — Итоговая приёмка и доставка

После T260a. Пользователь разрешил очередь исправлений, коммиты, push и deploy.

Результат: проверенные точные версии frontend/API и подготовленных ops доставлены;
рабочие данные сохранены. Не активировать независимые alert timers без канала.
Файлы реализации не менять; при обнаруженном дефекте выделить отдельную карточку.

Порядок:
1. Полный npm run check, build:api, Python deploy tests, verify_build и API units.
2. Проверить remote/clean diff, сохранить прежние ops и API target для rollback.
3. Обновить ограниченный deploy receiver и offsite receiver после их проверок.
4. Свежая зашифрованная внешняя копия с подтверждением SHA до migration016.
5. Push dev, успешный CI/frontend; отдельный API artifact SHA, npm ci --omit=dev,
   migration016 и атомарный current. Namespace journal и public static gzip по runbooks.
6. Live health/readiness/401, публичный browser smoke, release SHA, compression,
   сохранность данных по закрытому агрегатному сравнению без вывода записей.
7. Зафиксировать реальные команды/версии/CI/ограничения в документации,
   итоговый docs commit и push/CI. Не заявлять API SHA равным docs-only frontend SHA.

Приёмка: обязательные gates PASS; свежая внешняя копия подтверждена;
production SQL не используется для тестов; точные component SHAs записаны;
откат доступен; независимые alerts и универсальный JSON export честно открыты.

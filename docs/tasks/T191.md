# T191 — API регистрации и восстановления по email

Зависимость T190. Результат: POST /auth/email/register (email/timezone),
/request (email/purpose), /complete (token/purpose/password) под /api/v1.
Регистрация email-first: пароль задаётся после получения ссылки. У существующего
подтверждённого аккаунта регистрация не меняет ничего; request поддерживает
повтор verify и reset только подтверждённого адреса.

Общая ASCII-политика T188: trim, lower только домена, сравнение адреса без
учёта регистра. 32 случайных байта hex в ссылке #auth=purpose&token=..., SHA-256
в БД. Origin берётся из серверной конфигурации. Секрет не передаётся в query.
Одинаковый 202 для неизвестного/известного/ограниченного email, SMTP не задерживает
ответ. Наличие/ошибки доставки не раскрываются; повтор возможен через минуту.
Лимиты в памяти: 30/min/IP, 5/15min/email для выдачи; 10/15min/IP для погашения.
Один общий предел четырёх хеширований с прежними регистрацией и входом.
Без SMTP выдача/погашение недоступны, нет токенов в ответах/журналах.
Origin обязателен; данные токен-маршруты публичные, без session CSRF, поскольку
секрет ссылки является разрешением. Привязка старого аккаунта будет требовать CSRF.

Файлы: domain/emailAccount.ts, server/emailAuth.ts, auth.ts, httpSecurity.ts,
accountMail.ts (переиспользование адреса), тесты и документы; до 250 строк.
Проверки: нормализация/границы/неверный ввод, SMTP-заглушка без внешней сети,
одинаковые ответы, секреты только в письме, лимиты, Origin, повтор/expiry,
пароль и удаление сессий; npm run check, build:api, diff check.
UI и рабочий VPS пока прежние.

# T190 — Ограниченные SQL-операции email-аккаунта

Зависимость T189. Запрос пользователя разрешает завершить T190–T196
последовательно, с проверками и отдельным коммитом каждого этапа.
Далее: API, email-вход/привязка старых аккаунтов, регистрация UI,
восстановление UI, E2E, публикация.

Результат T190: миграция 013 предоставляет runtime только фиксированные функции
создания ожидающего подтверждения аккаунта, выдачи токена и его погашения.
Новые аккаунты требуют подтверждения email; пароль задаётся при погашении,
первоначальный хеш — недоступный пользователю случайный секрет backend.
Старые аккаунты не требуют email автоматически.

verify_email действует час, reset_password — 15 минут. Повторная выдача не чаще
минуты, заменяет прежнюю ссылку. Подтверждённый адрес не перерегистрируется.
Погашение проверяет назначение, адрес, время и одноразовость; атомарно меняет
пароль, подтверждает email (для verify), удаляет сессии и остальные токены.
Блокировки пользователя сериализуют выдачу/погашение; API входа начнёт брать
такую же блокировку в T192. Привязка старого аккаунта добавляется в T192.

Файлы: migrations/013_email_operations.sql, PostgreSQL-тесты и статусы.
До 250 строк SQL, без новых зависимостей. Проверки: runtime-права, обычные/
неверные/пустые данные, сроки и границы, дубли, замена, изоляция, конкурентное
погашение, сохранение прежних пользователей; npm run check, build:api, diff check.
UI не меняется; рабочая БД пока не обновляется.

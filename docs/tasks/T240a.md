# T240a — Объяснение ротации и смены поколения

Зависимость: T240. IMP-009 / AUD-006. Статус — в TASKS.md.
Результат: client/http принимает только409 command_rotation header с локальным
безопасным сообщением «команда не сохранена»; error body не читается.
notices сообщает смену generation того же аккаунта после epoch/remount:
несохранённый ввод сброшен, нужно проверить записи. Для generic409/lost response
не обещает, что прежняя операция не сохранена. Другой owner/logout очищают notice;
initial diary/revision refresh не дают ложное сообщение.
Реализация: client/http/notices/QueryFeedback (3/250), без новых зависимостей.
Регрессия: safeheader/status; epoch notices/crossowner/initial; настоящие
API hooks + AuthBoundary/App, текст/File mediaform→GET новогоgeneration→
remount пустой формы + заметное notice. Успешные подтверждённые записи не меняются.
Проверки: FAIL до изменения; связанные client/AppVisibility/backup tests,
types/lint/browser по применимости, docs/diff/staged review.
Полный check/build:api — перед разрешённым выпуском очереди.

Расширение в пределах бюджета: при исчезновении сфокусированного редактора
сообщение получает фокус только если он оказался на body; другое доступное
поле не перехватывается. Закрытие notice возвращает фокус в main.
Регрессия unit+E2E keyboard/focus, без новых стилей.

На media после успешного чтения visibility существующий App effect может
перевести фокус из notice в main; обе конечные позиции осмысленны и проверены
после полной загрузки, body/удалённый input не принимаются.

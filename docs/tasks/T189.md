# T189 — SMTP-транспорт служебных писем backend

Зависимость: T188. Результат: backend предоставляет внутренний accountMail
для передачи одного текстового служебного письма локальному Postfix.
Публичного маршрута отправки нет; генерация ссылок/токенов и формы — отдельно.

Область: src/server/accountMail.ts, runtime.ts, package.json/lock,
.env.example, тесты и краткая документация. Nodemailer 10.1.1 фиксируется
точно; npm registry подтверждает Node >=20 и встроенные типы, Node проекта 24.
Основание: [SMTP transport](https://nodemailer.com/smtp).

MAIL_ENABLED=false по умолчанию: никакой SMTP-сети, accountMail=null.
При true транспорт использует только 127.0.0.1 и MAIL_SMTP_PORT (по умолчанию 25),
без пароля, pooling и SMTP-логов. Локальный канал без STARTTLS: трафик остаётся
на VPS; внешний TLS/DKIM обеспечивает Postfix из T186–T187. Не разрешать
настройку удалённого SMTP через этот транспорт. Ошибочные настройки отклоняются.

Отправитель фиксирован no-reply@auth.arturican.com; один ASCII dot-atom адрес
по политике T188, тема 1–120 символов без CR/LF/control, текст 1–8192 символов
без NUL. Сервис принимает только эти три поля, без HTML, вложений и файлов/URL.
Не более четырёх одновременных отправок; лимит попыток по пользователю/IP
вводится вместе с будущим recovery API. Подключение/приветствие/idle ограничены
5/5/10 секундами. Нет прикладных повторов при неизвестном результате DATA.

Критерии: disabled/валидная/неверная конфигурация; формат и границы ввода;
реальный SMTP-диалог только с локальной синтетической фикстурой, один envelope
recipient и UTF-8 письмо; отказ SMTP/обрыв/таймаут дают обобщённую ошибку без
адресов, текста, исходной ошибки; лимит и освобождение слота после ошибки;
создание/закрытие сервиса с API. Приём Postfix не означает доставку во входящие.

Проверки: целевые тесты, npm run check, npm run build:api, git diff --check.
Рабочий VPS/env не меняются; реальным получателям письма не отправляются.
В UI по-прежнему можно проверить обычную регистрацию/вход; новых форм нет.

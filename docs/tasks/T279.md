# T279 — Проверенный кандидат итогового выпуска

Зависимости [T278](T278.md) и подтверждённый вариант контроля [T276](T276.md).
Результат — зафиксированный локальный кандидат и применимые проверки доставки.

1. Сверить результаты T274–T278 и открытые ограничения. Указать точный коммит
   кандидата, диапазон кода от последней принятой версии и затронутые части.
   Сверить frontend, API, миграции, зависимости, ops и пользовательский контракт.
2. На отдельной локальной базе и синтетических данных выполнить `npm run check`
   или `npm run local:check` с теми же обязательными этапами, затем
   `npm run build:api`. Записать точку входа, SHA и итог каждого обязательного этапа.
3. Прогнать применимые проверки из PROJECT_MAP. Для упаковки фронтенда выполнить
   `python3 -B deploy/verify_build.py dist`, для deploy-скриптов — предусмотренный
   Python suite. При изменении unit или Nginx добавить их штатные native gates.
4. Сопоставить ожидаемые запросы frontend и ответы API для обеих промежуточных
   комбинаций версий. Выбрать совместимый порядок доставки и предыдущие версии
   для отката. Не считать миграцию безопасной без сравнения по штатному регламенту.
   Если API нельзя обновить первым, согласовать совместимый переход или новый
   порядок и обновить зависимости T280–T282 до доставки.

Готово, когда все обязательные проверки прошли для выбранного кода, зафиксированы
совместимость и откат, а блокирующие дефекты закрыты. Исправления разнести по
карточкам и повторить нужные проверки. Коммит отчёта может быть новее кандидата.
Для доставки брать зафиксированный SHA. `check:docs`, diff, TASKS/PROGRESS и один
локальный коммит по приёмке кандидата.

# T279 — Проверенный кандидат итогового выпуска

Зависимости [T278](T278.md) и подтверждённый вариант контроля [T276](T276.md).
Результат — зафиксированный локальный кандидат и применимые проверки доставки.

1. Сверить результаты T274–T278 и открытые ограничения. Указать точный коммит
   кандидата, диапазон кода от последней принятой версии и затронутые части.
   Сверить frontend, API, миграции, зависимости, ops и пользовательский контракт.
2. На отдельной локальной базе и синтетических данных выполнить `npm run check`
   или `npm run local:check` с теми же обязательными этапами, затем
   `npm run build:api`. Записать точку входа, SHA и итог каждого обязательного этапа.
3. Прогнать применимые проверки из PROJECT_MAP. Для упаковки фронтенда выполнить
   `python3 -B deploy/verify_build.py dist`, для deploy-скриптов — предусмотренный
   Python suite. При изменении unit или Nginx добавить их штатные native gates.
4. Сопоставить ожидаемые запросы frontend и ответы API для обеих промежуточных
   комбинаций версий. Выбрать совместимый порядок доставки и предыдущие версии
   для отката. Не считать миграцию безопасной без сравнения по штатному регламенту.
   Если API нельзя обновить первым, согласовать совместимый переход или новый
   порядок и обновить зависимости T280–T282 до доставки.

Готово, когда все обязательные проверки прошли для выбранного кода, зафиксированы
совместимость и откат, а блокирующие дефекты закрыты. Исправления разнести по
карточкам и повторить нужные проверки. Коммит отчёта может быть новее кандидата.
Для доставки брать зафиксированный SHA. `check:docs`, diff, TASKS/PROGRESS и один
локальный коммит по приёмке кандидата.

## Кандидат и совместимость — 25.11.2026

Точный SHA кандидата — `91965fcb4302302d778b5650692f187cfeb7fe7f`.
Отчёт T279 фиксирует результаты для этого SHA, а его собственный коммит
создаётся после проверок.

Подтверждены зависимости T274–T278. Учение восстановления прошло, владелец
подтвердил восстановление свежей внешней копии и доступность защищённой копии
ключа. Решение T276 принимает действующую почту резервирования. При полном
отказе VPS базы данных его монитор тоже остановится, AUD-011 остаётся открытым.
T278 подтвердил полный перенос года со 100 МиБ вложений в Desktop Chromium
и эмуляции Pixel 7. Физический телефон требует отдельной проверки.

### Диапазон изменений

Опубликованный frontend на момент проверки — `93fa0d48799e0c9c859e3ed39b0c8d5291315f51`,
совпавший с HTTPS `release.txt`. API активен, `current` указывает на
`/opt/health-api/releases/T260-b58094a19844`. Его принятый срез —
`b58094a198444e1547993c3f10e58d7d61b2e2c1`.

Сравнение frontend выполнено от `93fa0d4`, API — от `b58094a` до кандидата.
Изменения пользовательского кода входят в T270–T272. Графики и итог питания
используют один запрос, полная копия скачивается из проверенного Blob,
обработка записи фото и документов выделена в общий серверный шаг.
Также добавлены скрипты переносимой разработки, тесты и документация.
Зависимости, lockfile и версии среды совпадают с принятым API.
Изменения CI расширяют native-проверку monitor units, deploy helpers включают
изолированный development secrets helper. К выпуску применяется решение T276.

### Порядок доставки и откат

В T280 сначала поставляется API кандидата отдельным артефактом, затем в T281
frontend через штатный CI. Перед доставкой повторно сверяются фактические
`current`, `release.txt` и свежесть внешней копии по карточкам доставки.

Для отката API сохраняется `/opt/health-api/releases/T260-b58094a19844`.
Frontend возвращается на принятый `93fa0d48799e0c9c859e3ed39b0c8d5291315f51`
атомарным переключением по DEPLOYMENT. Обе промежуточные комбинации используют
одни контракты и текущую схему. Процедуры переключения и проверка доступности
после них выполняются на этапе доставки.

Точка входа полного gate из каталога клона при готовой тестовой БД:

```bash
source ~/.nvm/nvm.sh
nvm use
export TEST_DATABASE_URL=postgresql://postgres:synthetic-local-only@127.0.0.1:55432/health_test

npm run check
npm run build:api
python3 -B -m unittest discover -s deploy -p 'test_*.py' -v
python3 -B deploy/verify_build.py dist
python3 -B deploy/verify_api_units.py
systemd-analyze verify deploy/health-backup-monitor.service deploy/health-backup-monitor.timer deploy/health-watchdog.service deploy/health-watchdog.timer deploy/health-offsite-monitor.service deploy/health-offsite-monitor.timer
npm run test:local
npm run test:secrets:local
```

отчёта повторно прошли `check:docs` и diff check. Успешный локальный gate
подтверждает кандидат для следующего этапа. CI, доставка и живая приёмка
этого кандидата выполняются в T280–T282.

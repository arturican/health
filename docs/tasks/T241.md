# T241 — Безопасные локальные диагностические события

Зависимость: T240a. IMP-010 / AUD-009. Статус — в TASKS.md.
Результат: internal500 и отказы доставки registration/reset/binding дают
allowlisted event в локальный stderr, публичные ответы/enum protection прежние.
Только version/time/случайныйid/event/suppressed count; без адреса/account/IP/
URL/body/token/SQL/exception/stack. Успех/обычные4xx не создают ложных событий.
Не более30 events каждого из трёх типов в60s на API instance, suppressed
счётчик ограничен; writer failure не меняет ответы и не рекурсирует.
Никаких внешних отправок. Retention отдельной T241a (до выпуска), не обещать
настроенное хранение только по наличию logger.

Реализация: server/diagnostics,app,emailAuth,emailBinding (4/250); mailer logger
остаётся отключён, двойного события нет. Factory/writer injection для
детерминированных privacy/rate tests, Fastify decorator общий для auth.
Регрессия: synthetic500 и SMTP failures дают один фиксированный event;
данные/sentinel отсутствуют, success/invalid input без событий; rate/window/
suppressed/backwards clock/writer fault и размерстроки≤256bytes.
Связанные API/mail tests, build:api/lint/docs/diff/staged review.
Общий check и retention deployment — перед выпуском.

Read-only review выявил async EPIPE исходного process.stderr.write.
Регрессия child IPC (env пустой, отдельный закрываемый pipe, без задержек)
FAIL exit1 до исправления; default sink использует короткий writeSync(fd2)
в существующем try/catch, после — alive и exit0. Новых stream/global handlers нет.

# T282 — Итоговая приёмка и передача сопровождения

Зависимость [T281](T281.md). Результат — проверенная пара установленных версий
и запись, по которой дальнейшее сопровождение можно продолжить из нового сеанса.

1. Сверить `release.txt`, фактический API `current`, SHA256 артефакта, весь CI
   и наличие согласованного отката. Проверить health/readiness, HTTPS и
   недоступность приватного маршрута без входа.
2. По штатному регламенту запустить
   `npx playwright test --config tests/deployed/playwright.config.ts` с ожидаемым
   полным SHA и локальным закрытым синтетическим демо. Проверить профиль и вес,
   «Сегодня», питание, активность, фото, документы и настройки, включая
   чтение после сохранения, скачивание и выход. Убедиться в сохранности
   исходных демо-данных после CRUD. Проверки затрагивают только согласованный
   синтетический аккаунт. Формы регистрации и восстановления проверяются
   штатными сценариями, получение реальной почты подтверждается отдельно при
   изменении почтового контура и с разрешением.
3. Сверить наличие свежей внешней копии, результат восстановления T275,
   применённый способ наблюдения T276 и подтверждённый профиль T278.
   Записать дату, версии, проверки Desktop/Pixel 7, ограничения и порядок
   действий при сбое в DEPLOYMENT/PROGRESS. Если изменилась обещанная ёмкость,
   обновить соответствующий раздел руководства пользователя.

Готово, когда выполнены критерии [плана выпуска](../RELEASE_PLAN.md#когда-выпуск-считаем-готовым).
Провал критического сценария блокирует приёмку. Зафиксировать воспроизведение,
согласовать малую задачу исправления или выполнить проверенный откат.
`check:docs`, diff, один локальный коммит приёмки и обновление TASKS/PROGRESS.

## Объём живой проверки

Для этой приёмки штатный diary.spec.ts дополнен helper attachmentSmoke.ts.
Загрузка геометрического фото проходит браузерную подготовку JPEG. Сверяются
размеры и цвет изображения, байты отображаемого Blob и файлового API.
Синтетический PDF сверяется с исходными байтами после загрузки и скачивания.
Собственные временные ID удаляются в finally, файловый API после очистки
возвращает 404.

Сохранность исходного демо проверяется SHA256 полного JSON-снимка до и после
CRUD. Из сравнения исключается время экспорта. В снимке остаются все записи,
связи, настройки и байты файлов. Фикстура входа допускает только health-demo.

# T233 — Черновики медиа при сбое видимости

Зависимость: T232a. Статус — в TASKS.md. IMP-002 / AUD-001.
Результат: App сохраняет формы/выбранный File при failed refresh и pending retry
того же аккаунта; последняя успешно принятая visibility отделена от failed.
Кеш не принимает старый async ответ; epoch/generation смены не используют
прошлую видимость. Начальная неизвестность скрыта; явный hide/logout работают.

Реализация: src/ui/useVisibility.ts, src/App.tsx, src/pages/PrivacySettings.tsx
(нейтральный текст ошибки), PhotosPage и DocumentsPage (StorageBoundary
для читающих карточек отдельно от редактора). До5 app-файлов, до250строк.
Расширение внутри бюджета обусловлено новым E2E FAIL: initial LabTrends
отказ во время заполнения документа размонтировал весь экран.
Тесты: src/AppVisibility.test.tsx с настоящими API hooks, unit useVisibility/
App/PrivacySettings и локальный E2E stale-media с настоящим API/PostgreSQL.
Файлы не отправляются наружу, только синтетические fixtures.

Приёмка: обе формы text+File переживают отказ, немедленный retry с deferred GET,
успех; fresh hide побеждает старый задержанный ответ и следующий отказ;
новый epoch не раскрывает прежние флаги/черновик; исходный объект visibility
не клонируется, recordRevision сохранена. Error/loading/retry различимы.
Регрессия FAIL до изменения, связанные tests/lint/typecheck и E2E; docs/diff/
staged review. Общий check/build:api после очереди перед разрешённым push.

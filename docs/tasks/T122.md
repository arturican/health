# T122 — сообщать о недоступной локальной базе при запуске

Основание: согласованные аудиты, QA-03 / UX-04. Зависимость: T121.

- При отсутствующем API IndexedDB либо отказе доступа к самому API приложение
  показывает доступное сообщение с инструкцией вместо бесконечной загрузки.
- Проверка выполняется до монтирования компонентов с liveQuery. Она не меняет
  данные, не очищает базу и не подменяет существующую обработку ошибок запросов.
- Production regression ограничивает API через addInitScript до импорта Dexie,
  проверяет прямые маршруты и сохранность синтетического дневника после возврата
  доступа. Поздний unit mock не считается подтверждением стартового отказа.
- Обычные сценарии приложения продолжают работать; нет зависимостей и сервера.

Область: App, App.test, новый storage-unavailable E2E, TEST_CASES и статусы.
Проверки: production RED, targeted unit/E2E GREEN, axe/нет внешних запросов,
полный `npm run check`, `git diff --check`.

Коммит: `fix(storage): T122 сообщать о недоступной базе при запуске`.

## Проверено

Production RED: отсутствующий до module load API оставлял маршрут веса
без ожидаемого сообщения. После исправления targeted App 12/12 unit и 4/4 E2E
(два отказа × desktop/mobile) PASS. На каждом отказе проверены три прямых
маршрута, axe, reflow и сохранность профиля/веса после возврата доступа.
Первый общий gate остановился на лишнем optional chain; проверка заменена на
typeof без ослабления ESLint. Итоговый `npm run check` PASS: 1091 unit,
90 Native Browser, production build и 46 E2E, документы, lint, типы, coverage.
Node 24.22.0 / npm 11.19.1, системный Chromium 154 через override;
прежнее предупреждение JS chunk >500 kB сохраняется.

# T192 — Email-вход и привязка прежнего аккаунта

Зависимость T191. Результат: подтверждённый email используется для входа без
учёта регистра; прежние login/password продолжают работать. Новые email-аккаунты
не входят по техническому login или до подтверждения. Смена пароля и создание
сессии сериализованы блокировкой пользователя; старый хеш не создаст новую сессию.

GET /api/v1/auth/email показывает только почту текущего аккаунта. POST /bind
требует сессию, Origin/CSRF и текущий пароль, общий предел четырёх Argon2-операций,
ограничение попыток. Только первичная привязка: подтверждённый email не меняется.
Ссылка verify хранит желаемый email в токене, не изменяет аккаунт до погашения;
при подтверждении пользователь задаёт пароль, все сессии отзываются.
Конфликт адреса не перехватывает другой аккаунт и не раскрывается публично.

Файлы: миграция 014, sessions.ts, auth.ts, emailBinding.ts,
domain/emailAccount.ts; тесты и документы. До 250 строк реализации.
Проверки: старый/email-вход, неверный/пустой ввод, подтверждение/регистр,
Origin/CSRF/владение/пароль/лимит, конфликт, повтор, сохранение дневника,
конкуренция сброса со входом; полный npm run check, build:api, diff check.
UI в T193–T194, VPS в T196.

# T209 — Расписание мониторинга и готовность внедрения

Зависимость: T208. Статус — в TASKS.md.

Результат: локальный комплект service/timer + JSON example для T208;
проверка unit-файлов в CI, инструкция установки/диагностики/отката.
Таймер раз в час, случайная задержка до пяти минут, Persistent;
state root 0700, конфигурация root 0600, сеть только loopback.
Пример получателя синтетический, оператор заменяет его при отдельном внедрении.
Допуск возраста в примере 30 часов, оператор явно выбирает значение.

Критерии: systemd-analyze verify принимает оба файла; диагностический smoke
реального CLI на временном синтетическом каталоге выдаёт JSON без SMTP/state;
пример проходит validate_config; 38 Python deploy, docs/diff check.
Приложение/алгоритм T208 не меняются, последний полный check — T208.
Production и фактическая доставка требуют отдельной задачи/разрешения.

Файлы приложения/доставки: два unit-файла, example JSON, workflow — до 5 файлов,
до 250 строк. Документы: BACKUPS, TESTING/PROJECT_MAP, TASKS/PROGRESS, карточка.
Один локальный коммит; не включать timer, не отправлять настоящие письма,
не менять 7/14 retention и не удалять архивы/состояние уведомлений.

# T278 — Экспорт и импорт согласованного объёма

Зависимость [T277](T277.md). Результат — подтверждённый пользовательский путь
переноса или точное воспроизведение ограничения, мешающего ему.

1. Подготовить только синтетические данные и вложения в выделенной локальной
   БД. Привязать воспроизводимый сценарий к числам T277. Взять за основу текущий
   E2E полного восстановления и фикстуры двух разных аккаунтов.
2. В браузере скачать копию, проверить предпросмотр и восстановить её во второй
   синтетический аккаунт. Сравнить содержимое, связи и байты файлов одинаковым
   способом до и после. Сверить, что приватный API сохраняет границу владельца.
3. Измерить размер и время на согласованной среде. Для пограничного сценария
   проверить понятное сообщение `413` и отсутствие изменений в данных. Объёмные
   замеры запускать отдельно от обычного CI с ограниченной нагрузкой.
4. Записать подтверждённый профиль в BACKUP_CAPACITY и руководство. При `413`
   на целевом наборе выбрать поддерживаемый объём с владельцем или согласовать
   отдельный проект формата, затем повторить этот шаг.

Готово, когда согласованный профиль прошёл круговой перенос и пограничный
отказ безопасен. Файлы поиска: `backupRoutes.ts`, `fullBackup.ts`,
`backupRepository.ts` и настройка экспорта и восстановления. При исправлении
дефекта выделить отдельную карточку. Связанные E2E, `check:docs`, diff и один
коммит по результату с TASKS/PROGRESS.
[Полный сценарий](../../tests/e2e/full-restore.spec.ts) · [Повреждённый файл](../../tests/e2e/invalid-full-backup.spec.ts) · [Ёмкость](../BACKUP_CAPACITY.md)

## Результат 25.11.2026

Два проекта Chromium выполнили полный перенос года со 100 МиБ вложений между
двумя синтетическими аккаунтами. JSON — 141 405 056 байт, сверены записи,
связи и SHA256 всех 76 файлов. Исходный аккаунт и его ревизия сохранены.
Предпросмотр отверг файл 200 МиБ + 1 байт до POST. API вернул 413 при
превышающем лимит Content-Length, снимок и ревизия сохранились.

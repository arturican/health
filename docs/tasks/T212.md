# T212 — Детерминированный предел параллельных проверок пароля

Зависимость: T211. Статус — в TASKS.md.

Основание: auth.test.ts проверяет число успешных ответов на восемь запросов,
но SQL/хеширование могут завершаться последовательно; T206 наблюдал 5 вместо 4.
Требование продукта — максимум четыре ОДНОВРЕМЕННО выполняемых проверки.

Результат: управляемый барьер в тесте удерживает четыре verifier-вызова,
следующие запросы получают 429 до освобождения; после освобождения вход работает.
Настоящая проверка Argon2 и остальные auth-тесты сохраняются, задержек/sleep нет.
Минимальная явная инъекция verifier в registerAuthentication допустима для этого
наблюдаемого сценария; лимиты/SQL/пароли production не менять.

Файлы: server/auth.ts и auth.test.ts, TASKS/PROGRESS, связанная запись IDEAS.
Бюджет до 5 файлов приложения и 250 строк реализации, без зависимостей.
Проверки: целевой auth.test.ts, npm run check, Python deploy, diff check.
Один локальный коммит, без push/деплоя.

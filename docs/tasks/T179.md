# T179 — Проверки перед публикацией dev

Зависимость: T178b. Пользователь явно разрешил полное тестирование, коммиты,
push и деплой. Проверить чистоту рабочего дерева и актуальность origin/dev.
Выполнить npm run check, build:api, Python deploy tests и verify_build.
Зафиксировать результаты в TASKS.md и PROGRESS.md отдельным коммитом.
После коммита по тому же запросу отправить dev без force; дождаться CI
и публикации проверенного frontend. Эти внешние действия подтверждаются итоговым
отчётом, а не преждевременным заявлением об успехе в коммите.
После доставки проверить ожидаемый SHA, HTTPS, все восемь экранов, CRUD и
вложения существующим Desktop/mobile smoke для синтетического health-demo.
Проверить API, резервное копирование и неизменность состояния Remnawave.

Backend уже опубликован; при отсутствии изменений его артефакта достаточно
сверки файлов и работоспособности. Не перезапускать shared PostgreSQL,
Remnawave и другие чужие сервисы. Не изменять схему/seed при повторном деплое.
Найденные ошибки оформлять отдельными небольшими задачами с regression-тестами.
Фактический результат push/CI/deploy сообщить после коммита без обещания успеха.

# T254 — Сохранять подтверждённый SHA копии

IMP-023 после T253. Разделение до реализации: T254 — manifest при приёме;
T254a — read-only offsite probe и запуск; T254b — синтетическое восстановление.
Транспорт уведомлений остаётся T252a/T253a, не заявлять его работающим.

Файл реализации: deploy/backup_receive.py. После проверки входного потока и
совпадения target сохранять expected SHA256 в отдельном файле .sha256 через
временный файл 0600, fsync и atomic replace. Оба файла публикуются под уже
существующим receive lock. Ошибка manifest не подтверждает приём: безопасный
идемпотентный повтор завершит публикацию. Retention 14 удаляет и sidecar
только соответствующего удалённого дневника; cluster/unrelated сохраняются.

Регрессии: успешный приём/replay, ошибочный SHA не публикует manifest,
сбой atomic replace не теряет ciphertext и повтор безопасен; symlink не
разыменовывается, режим 0600, retention. Python tests, docs/diff.
На VPS установка и backfill ещё не выполняются; это release step T260.

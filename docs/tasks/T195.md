# T195 — Сквозное восстановление и финальная проверка авторизации

Зависимость T194. Результат: Chromium desktop/mobile проходит весь email-путь
через UI и локальный SMTP: регистрация/пароль/вход, reset, старый/новый пароль,
две вкладки и отдельная сессия другого устройства, использованная/истёкшая
ссылка, повтор verify, первичная привязка с сохранением профиля, axe/адаптивность.
Программное погашение в registration E2E заменяется экраном пароля.

Финальные исправления: успешное погашение очищает текущую cookie (в том числе
когда в браузере был другой аккаунт), не создаёт сессию; неуспешное её не меняет.
Публичная модель аккаунта дополнена необязательным email для блока аккаунта; старые
аккаунты/ответы без email совместимы, пароль/внутренние поля не раскрываются.
Файлы приложения: server/emailAuth.ts, sessions.ts, domain/session.ts,
client/AuthBoundary.tsx; до 250 строк. Остальные файлы — тесты/документация.

Тестовый сервер имеет только локальные mailbox и часы. Перед новым recovery
сценарием часы переходят на 16 минут в рамках того же синтетического дня,
чтобы независимые тесты не делили окно лимита; сами лимиты не отключаются.
Expiry изменяется только у конкретного синтетического хеша в изолированной
health_test_UUID. Продакшен не содержит этих маршрутов/фикстур.

Проверки: целевые API/unit и E2E, полный npm run check, build:api, diff check.
Обновляются PRIVACY_SECURITY/MAIL_DNS/DEPENDENCIES. Никаких настоящих писем,
медицинских данных или внешних сетевых сервисов в тестах. VPS — T196.

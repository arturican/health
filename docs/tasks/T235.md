# T235 — Явное восстановление настроек и плана после конфликта

Зависимость: T234. IMP-004 / AUD-003. Статус — в TASKS.md.
Результат: PrivacySettings/EnergyPlanForm предлагают явное отбрасывание ввода
и загрузку текущего успешно прочитанного snapshot. До выбора повтор использует
старую ревизию, не перезаписывает чужие изменения. Pending/failed read не
разрешают сброс. Фокус возвращается в доступное поле.

Реализация: два файла форм (до5/250). Новые зависимости отсутствуют.
Регрессия на настоящих API hooks: R1 draft → сервер R2 →409 → GET R2,
draft сохранён; повтор без выбора остаётся R1; явный сброс показывает R2,
следующая запись использует R2 и проходит. Сброс disabled во время pending.
Связанные unit/browser PrivacySettings/EnergyPlanSettings, types/lint/docs/diff/
staged review. Полный check/build:api — перед push очереди.

После explicit load R2 следующий GET R3 не повышает исходный snapshot:
regression FAIL до фикса, Save остаётся на R2 до нового явного выбора.
Повтор чтения visibility сохраняет ввод; отдельная кнопка отбрасывает его.
Связанный Browser обновлён под подтверждённый контракт T233: failed refresh
сохраняет последнюю известную visibility, unknown initial по-прежнему скрыт.

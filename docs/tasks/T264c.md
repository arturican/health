# T264c — Короткая инструкция и проверка SSH setup в чистом клоне

Зависимость T264b. Результат: первый запуск без ручного переноса age key/SOPS,
одна setup команда после Node/Docker/разрешения SSH public key. Обновляются
README/DEVELOPMENT/PROJECT_MAP/AGENTS/DEPENDENCIES, комментарии безопасных
env templates и журнал; конфигурация runtime не меняется.

Проверки: git clone --no-local только tracked code, PATH без SOPS/age,
отсутствующий SOPS_AGE_KEY_FILE, явно предоставлен только существующий SSH
identity. Setup сам выполняет npm ci, restore через реальный restricted VPS,
локальную БД/миграции/seed на новых портах/томе; повторный setup/smoke сравнивает
все таблицы и подтверждает отсутствие повторной установки зависимостей.
Default Node tests, full local:check/build:api, verify_build, docs/diff/staged
и скан task logs на секреты. Python95 уже PASS в T264a; код helper не менялся.

Push в прежнюю feature-ветку без force по исходному разрешению. Production
приложение, БД, VPS deploy/timers остаются прежними; изменён только явно
разрешённый development secrets helper. CI feature push автоматически не идёт.
Второй физический компьютер и выдача доступа его неизвестному public key не
проверяются; действующий ключ этого компьютера проверен. Приватный ключ на новый
ПК не копируется и в репозитории отсутствует. Offline backup не создан.

Факт: чистый setup + default Node4 + повторный setup/smoke PASS, full check
1726 unit/API + 92 Browser + 100 E2E PASS, build:api/verify_build PASS.
Выдача нового временного public key проверена живым decrypt и shell denial,
временный доступ отозван, прежний доступ перепроверен. Данные не менялись.

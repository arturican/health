# T206 — Локальная проверка состояния резервных копий

Зависимость: T205. Статус — только в TASKS.md.

Результат: оператор получает JSON и exit code для свежести последнего локального
архива приложения и результата health-backup.service. Порог возраста задаётся
явно положительным конечным числом часов. Возраст считается по UTC-времени
снимка в штатном имени, не по mtime; равенство порогу допустимо, будущее — ошибка.
Cluster baseline не заменяет копию приложения. Последний пустой архив, каталог
или symlink не скрывается за более старым валидным файлом.

Неизвестный/недоступный systemd, сервис без запуска после старта системы,
текущий запуск и неуспех не дают healthy. Проверка только читает метаданные
и systemctl show; не читает содержимое архивов, не обращается к сети/БД,
не удаляет копии и не меняет расписание/retention. Это не подтверждение
целостности, расшифровки, свежести offsite или доставки уведомлений.

Файлы: deploy/backup_check.py и тесты; BACKUPS, TASKS, PROGRESS и эта карточка.
Новых зависимостей, изменения API/UI и установки на VPS нет.

Проверки: синтетические свежесть/границы/пустота/неверные даты/symlink,
ошибки/отсутствие/текущий запуск systemd, JSON/exit code;
все Python deploy-тесты; npm run check; verify_build; git diff --check.

Один локальный коммит. Следующий этап — канал и контракт внешних уведомлений,
требующие отдельного выбора пользователя; production не изменяется.

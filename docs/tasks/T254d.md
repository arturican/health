# T254d — State/delivery артефакт offsite monitor

После T254a/b и выбора SMTP в T252a; входит в разрешённую очередь AUD-011.
Наблюдаемый результат — проверенные CLI/state/email policy и hourly units.
Установка/получение/активация остаются T254c после T262; эта задача не требует
готового публичного DNS и не включает service/timer на VPS.

Файлы реализации (≤5/250): deploy/offsite_monitor.py,
deploy/health-offsite-monitor.service, deploy/health-offsite-monitor.timer,
.github/workflows/check.yml (native unit gate; четыре implementation файла).
Тесты test_offsite_monitor.py, TASKS/PROGRESS/BACKUP_CONTROL отдельно.

Правила:
- Только фиксированный sibling offsite_check.py с существующими directory/30h,
  read-only ciphertext, без GPG/новых сетевых интеграций. Child timeout65s
  поверх штатного deadline60s, CLI80s, unit90s; неизвестный/невалидный результат
  считается unhealthy/unknown и может вызвать оповещение.
- По умолчанию dry-run без state/SMTP. --send: private directory0700,
  lock0600/owner/no-symlink, atomic state0600 и recipient hash. Не использовать
  state local backup/watchdog. Первое healthy молчит; первое unhealthy шлёт;
  повтор того же aggregate status не шлёт; healthy после ошибки — recovery.
- Busy receiver не объявляется healthy: conservative unhealthy alert,
  возможен одиночный alert при совпадении hourly check с передачей. Не
  скрывать длительный busy бесконечным pending. Новых порогов/retention нет.
- Тексты содержат только фиксированные status/freshness/integrity, без имён,
  hash, путей, содержимого/адреса в теле. Транспорт только loopback SMTP.
  SMTP refusal/error не ACK и не пишет новое состояние. Queue acceptance
  не равно inbox receipt; actual delivery доказывается отдельно T254c.
- Автотесты без внешней сети/произвольных задержек: healthy/missing/corrupt/
  stale/busy/unknown, дедупликация/recovery/recipient change/concurrent runs,
  SMTP failure, private/corrupt/symlink state и CLI redaction.
- Native systemd verify, full deploy Python tests, docs/diff/staged check;
  перед итоговым push полный check/build:api/deploy gates по WORKFLOW.

Не менять рабочий backup/receiver/watchdog, retention7/14, data, DNS или ключи.
Rollback артефакта: не установлен; для будущей установки сначала stop/disable
только новый timer, сохранить state/config, вернуть сохранённые версии.

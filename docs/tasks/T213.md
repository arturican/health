# T213 — Readiness API с проверкой подключения к БД

Зависимость: T212. Статус — в TASKS.md.

Результат: GET /api/v1/readiness сообщает 200 {status:'ready'} только при
доступном настроенном runtime pool; без БД или при ошибке — 503
{status:'unavailable'}. Существующий /health остаётся liveness процесса.
Проба SELECT 1 не читает данные дневника; query_timeout 1000 ms, ожидание
подключения ограничено существующим connectionTimeoutMillis=5000 ms.
При ошибке/тайм-ауте клиент уничтожается через release(true), не возвращается
в pool для следующего запроса. Детали БД/ошибки в ответ и логи не попадают.

Проверки: реальная выделенная БД, отсутствие/ошибка/восстановление пробы,
освобождение/уничтожение клиента и отсутствие утечки деталей; HTTP headers.
Runtime регистрирует readiness до listen и для режима без БД.
Никаких DDL, новых пулов/зависимостей, SMTP-проб и production-операций.

Файлы: server/readiness.ts и тесты, runtime.ts; документация TASKS/PROGRESS,
DEPLOYMENT/PRIVACY_SECURITY при изменении описанных фактов.
Проверки: целевые тесты, npm run check, build:api, Python deploy, diff check.
Бюджет до 5 файлов приложения / 250 строк. Один локальный коммит.

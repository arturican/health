# T215 — Push и выпуск завершённого backend

Зависимость: T214. Статус — в TASKS.md.

20.10.2026 пользователь явно разрешил push и деплой. Разрешены push dev,
штатная свежая зашифрованная внешняя копия, новый неизменяемый API-релиз,
установка production-зависимостей по lock-файлу, атомарное переключение current
и restart только health-api; доставка frontend через существующий CI.
При ошибке API вернуть прежнюю ссылку и проверить восстановление.
Не менять личные данные, секреты, схему/роли, SMTP, retention или другие сервисы.

Результат: SHA256 API-артефакта и установленных файлов совпадают, health/readiness
дают 200 локально и по HTTPS, приватные данные без сессии дают 401.
Проверить безопасные заголовки, состояние backup/monitor/tunnel и точный
frontend release SHA после успешного CI. Deployed smoke — только на синтетическом
demo без настоящих писем. Не имитировать отказ рабочей БД ради readiness 503:
этот сценарий уже покрыт локальными T213.

Проверки: действующие полные gates T213 для неизменённого кода, build:api,
docs/diff check; свежая внешняя копия, SHA256, права, HTTP и deployed smoke,
успешные check/deploy jobs. Файлы приложения не меняются. Один локальный
коммит с TASKS/PROGRESS/DEPLOYMENT и фактическим результатом, затем push.
При провале обязательной проверки задача остаётся незавершённой.

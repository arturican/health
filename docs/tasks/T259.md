# T259 — Решение о lazy routes

IMP-028 условный, после T258/T258a. Наблюдаемый результат — решение о
необходимости source refactor по измерениям, не обязательное добавление chunks.
Документы: COLD_LOAD/IMPROVEMENTS, TASKS/PROGRESS. Docs/diff checks.

Решение: lazy loading сейчас не внедрять. Локальный эксперимент показал
значительный transfer/FCP выигрыш от сжатия, не показал CPU или route regressions;
runtime JS после gzip≈149kB. Продуктового SLA на загрузку не обнаружено.
Сравнение с lazy-вариантом не выполнялось, поэтому не утверждать его бесполезность.
Добавление chunk/fallback/retry/old-tab поведения требует конкретной выгоды,
которую одним warning>500kB доказать нельзя.

T259 завершает решение, IMP-028 остаётся условным предложением, не implemented.
Вернуться после live compression proof и измеренного запроса на улучшение
конкретного маршрута/устройства. Тогда те же profiles+все8routes, keyboard,
chunk failure/retry и старая вкладка обязательны. Warning limit не повышать.

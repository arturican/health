# T223 — Свежесть запросов и защита тренировки

Зависимость: T222a. Статус — в TASKS.md.
P2: HTTPS-приёмка T222 выявила собственную устаревшую ревизию после успешного
сохранения; локальный быстрый refetch скрывал гонку. Это существующая клиентская
ошибка, а не изменение схемы/API. Данные не потеряны, исходные demo сохранены.

useDiaryQuery, legacy adapter, WorkoutJournal, Confirmation. Состояние current
синхронно устаревает после invalidate; старые данные/черновики сохраняются,
ошибка обновления не разрешает действия до успешного retry. Cancel подтверждения
остаётся доступен вне выполняющейся команды. Регрессии hook + реальный E2E
с задержкой GET после PUT, затем удаление revision2. Не менять recordRevision.

Проверки: regression с управляемым ожиданием/отказом, связанные unit/Browser/E2E,
lint/types/docs/diff; полный check и новый frontend-релиз — возобновлённая T222.
Отдельный коммит, затем следующий согласованный этап. Без новых зависимостей.

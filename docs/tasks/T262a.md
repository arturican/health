## Фактический результат 21.10.2026

- A mail-monitor, HELO SPF, shared auth SPF и новый DKIM TXT опубликованы.
  Google DoH подтверждает значения; native opendkim-testkey frontend PASS.
- Frontend deferred .invalid fixture: loopback/From/TLS/tempfail, RSA/body hash,
  own queue cleanup и journald privacy PASS. Отдельный rsyslog positive/negative
  контроль обоих sinks PASS. Реальных писем с frontend не отправляли.
- Data helper до обновления совпал с исходником185754f, чужих изменений нет.
  Сохранены before helper и JSON; в metadata добавлен sender_ips с обоими IP,
  прежние host/ip/sender/dkim_name/dkim_value сохранены. Первая защитная
  проверка installer отвергла дополнительные старые поля до записи; после
  учёта этих полей установка существующего кода прошла. Data --dns PASS,
  MTA config SHA256 неизменны, API/Postfix/OpenDKIM active.
- Google и Cloudflare: PTR NXDOMAIN, SOA negative TTL300. Прямой TCP DNS к
  ns1.beget.com и ns2.beget.com: authoritative=true, rcode3, PTR=[].
  Это подтверждает отсутствие записи в обратной зоне на момент проверки,
  а не только возможный кэш публичных resolvers.
- Официальная Beget инструкция направляет настройку PTR через тикет.
  Оператору дан готовый текст для IP159.194.208.200 → mail-monitor.arturican.com.
  Кабинет/тикет недоступны агенту; обращение не отправлялось инструментами.
- Helper/before на data: /root/health-T262 root0700; frontend stage сохранён.
  Приватные recipient/key не печатались. Data MTA не перезапускался.
  Frontend остаётся active/deferred и disabled на boot; новые timers выключены.

T262/T253a/T254c остаются blocked до PTR/receipt и отдельных приёмок.

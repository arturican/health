# T234 — Отмена устаревших редакторов

Зависимость: T233. IMP-003 / AUD-002. Статус — в TASKS.md.
Результат: Cancel четырёх редакторов доступен при failed reread; Save и поля
ждут свежих данных. Собственное pending сохранение блокирует Cancel.
Отмена только отбрасывает ввод; удаление/архивирование по-прежнему блокирует
конфликтующие поля и запись. Фокус переходит в main, затем при доступности
новой формы — в предусмотренное родителем поле.

Файлы реализации: ProductForm, FoodForm, WorkoutForm, LabForm и ui/actions.
До5 файлов, до250 строк. Новые зависимости отсутствуют.
Регрессия: настоящие API hooks и четыре родителя, failed products/workouts/
documents, сохранённый draft, disabled Save, enabled Cancel и возврат фокуса.
Существующие PendingEditors/WorkoutPending/LabSection и Browser проверки
подтверждают запрет отмены во время собственного сохранения.
Проверки: regression FAIL до исправления; связанные unit/browser, lint/types,
docs/diff/staged review. Общий check/build:api — перед push очереди.

Продолжающийся отказ products после Cancel еды проверен отдельно: новая форма
не имеет прочитанного списка и показывает существующий StorageBoundary с
повтором, без старого редактора; main сохраняет фокус. Автоматический успех
новой формы без сети не обещается. Отмена во время parent delete/archive
не прерывает операцию, её результат отображается, новая запись ждёт pending.

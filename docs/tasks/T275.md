# T275 — Операторская проверка свежей внешней копии

Зависимость [T274](T274.md). Результат — владелец подтвердил, что актуальную
копию можно восстановить. Нужны явное разрешение на необходимые операции,
доступ к внешнему архиву и оператор с доступом к защищённому ключу.

1. Сверить из доверенных источников время создания и SHA256 свежего архива на
   втором VPS. Проверить документированный допуск свежести для установленного
   расписания. Отдельно записать итоги проверки свежего файла и набора архивов.
2. Оператор подтверждает доступность защищённой копии ключа и успешную
   расшифровку. Ключ остаётся под его контролем вне VPS и Git.
3. Оператор выполняет закрытое восстановление по BACKUPS в новую
   `health_restore_<32 hex>` с запретом общего доступа. Рабочий API остаётся
   на своей БД. В закрытом контуре проверяются связи, байты, миграции, права
   и очистка восстановленных сессий и одноразовых ссылок. Проверочную БД
   по сохранённому точному имени убирают по регламенту и с разрешением.
4. В журнале зафиксировать дату и возраст снимка на момент проверки, результат
   сверки, успешность и длительность восстановления.
   Передавать только сводный итог. Ключ, dump, строки и байты не передаются Codex.

Готово, когда есть подтверждения всех шагов. `Unattested` у старых копий
отражается отдельно. Для подтверждения нужен доверенный источник SHA256,
а неподтверждённые копии остаются под правилами штатной ротации. Ошибка или
отсутствие доступа блокирует заключение о восстановимости свежего архива.
Запись результата в BACKUPS, TASKS/PROGRESS, `check:docs`, diff и один коммит.

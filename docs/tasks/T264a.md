# T264a — Изолированная расшифровка development secrets на VPS

Пользователь 21.10.2026 уточнил: секреты на VPS, получение автоматическое,
код/БД разработки остаются на компьютерах. Это разрешает только отдельное
development-хранилище/SSH helper; production env, сервисы, данные и деплой
не меняются. Исходная чистая ветка chore/portable-development, 46df0b2.

Очередь: T264a (VPS helper) → T264b (автоматические команды) → T264c (инструкция,
чистая копия, full gates, push той же feature-ветки по исходному разрешению).
Результат: существующий development age key переиспользован на frontend VPS,
закрытый отдельный каталог/user, только encrypt/decrypt через forced SSH command.
Ciphertext остаётся канонической версией в Git; ключ не скачивается на новые ПК.
Ранее запрещённый перенос production/recovery GPG ключей не выполняется.

Реализация: deploy/development_secrets.py, deploy/install_development_secrets.py,
config/development-secrets.json, config/development-secrets.known_hosts;
до 250 строк реализации. Python/OpenSSH уже установлены, SOPS 3.13.3 — тот же
проверенный бинарный файл, новых npm/pip dependencies нет. Публичный host key
получен через ранее доверенный StrictHostKeyChecking SSH, не через непроверенный scan.

Критерии: секреты только stdin/захваченный stdout; закрытый key600/dir700;
нет shell/PTY/forwarding, чужих env/путей/команд; лимиты/тайм-аут/проверка четырёх
DEV_* до и после SOPS, partial output при ошибке не возвращается. Установщик
повторяем, не заменяет иной существующий key, добавляет только явный public key.
Проверки: Python tests, реальный restricted SSH encrypt/decrypt и negative
command, повтор установки, отсутствие утечек; docs/diff/staged scan.
Семантика restrict/command — [OpenSSH](https://man.openbsd.org/sshd.8).

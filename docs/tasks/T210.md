# T210 — Внедрение мониторинга резервных копий

Зависимость: T209. Статус — в TASKS.md.

20.10.2026 пользователь запросил все этапы после предложения внедрения на VPS
и указал email-получателя. Разрешены установка T206–T209 на data VPS,
синтетические SMTP-письма ошибка/восстановление, включение monitor.timer.
Адрес — только в закрытой серверной конфигурации, не в Git/выводе.

Результат: хеши установленных файлов совпадают с проверенным локальным коммитом,
конфиг root 0600/state 0700, systemd verify и диагностический запуск проходят.
Синтетический тест под теми же sandbox-настройками отправляет ошибку один раз,
подавляет повтор, отправляет recovery; SMTP-принятие и внешняя доставка
проверяются раздельно по обезличенным результатам. Основной сервис стартует
успешно, почасовой таймер enabled/active, состояние резервирования проверено.

Сохранить прежние версии новых целевых файлов для отката. Не менять API/БД,
основной backup.service/timer, 7/14 retention, реальные записи/архивы/ключи.
Без новых зависимостей, push и frontend-релиза. При неудаче откатить только
мониторинг; подтверждение готовности — после обязательных проверок.

Файлы: карточка, TASKS/PROGRESS, BACKUPS, PRIVACY_SECURITY, MAIL_DNS и DEPLOYMENT
по фактическому состоянию.
Проверки: SSH с закреплённым host key, сравнение SHA256, права, systemd verify,
38 Python deploy, synthetic SMTP smoke, delivery-status, service/timer/rollback,
docs/diff check. Полный npm check T208 остаётся актуальным: код не меняется.
Один локальный коммит; при непроверенной доставке не объявлять её успешной.

# T176b — Создание, отправка и расписание копий

Зависимость: T176a. Четыре файла: Python sender, service, timer, JSON example.
pg_dump/pg_dumpall → GPG через pipes; на диск попадает только ciphertext.
Проверяется каждый процесс, размер, место, SHA256 при передаче по закреплённому
SSH host key. Локальная копия остаётся при отказе передачи; повтор отдельной
копии без создания новой. Retention: 7 локально, 14 на другом VPS, baseline
сохраняется. Секретный recovery key только локально, вне репозитория.

Установить отдельный forced-command SSH account, public encryption key и
получить исходную зашифрованную копию существующего кластера ДО изменений БД.
Timer устанавливается, но включается после создания health в T177.
Проверки: pipeline failure/limits, реальное GPG roundtrip synthetic,
передача baseline + совпадение SHA без расшифровки чужой БД, Python deploy,
полный npm run check, diff --check. Реальное восстановление health — T178.
Выявленная обязательным check гонка теста входа: ожидать фокус после React
эффекта через waitFor, сохранив то же требование. Production-код не меняется.

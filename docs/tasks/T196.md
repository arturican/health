# T196 — Опубликовать email-регистрацию и восстановление

Зависимость T195. Результат: проверенный код T190–T195 работает на
dev.arturican.com, backend/Postfix/БД остаются на прежних VPS/loopback.
Push/deploy разрешены прежним явным запросом пользователя и включены
в согласованную очередь завершения регистрации/восстановления.

Порядок: свежая успешная внешняя зашифрованная копия, проверенный SHA256
артефакта API, новый readonly release с npm ci, аддитивные 012–014 отдельной
migrator-ролью, MAIL_ENABLED=true/MAIL_SMTP_PORT=25 только в закрытом api.env.
Прежний env и release сохраняются. После restart — здоровье/службы/DNS,
публикация frontend через штатный проверяющий установщик. Старые данные и
сервисы не удалять, не читать медицинские документы/пароли в вывод инструментов.

Критерии: публичный release совпадает с выбранным артефактом, API health 200,
анонимные данные/email 401, тестовые маршруты 404, SMTP/OpenDKIM активны,
production Node/роль/включение почты проверены без раскрытия env.
Live Chromium desktop/mobile: прежний синтетический дневник и новые формы,
без отправки настоящим получателям. Доставка в реальный ящик не заявляется.
Локальные и CI проверки кода T195; Python deploy tests, verify_build,
docs/diff check. После публикации — один docs-коммит и push dev; итоговый CI
публикует тот же код с hash этого коммита, финальный hash сообщается пользователю.

Файлы репозитория: TASKS/PROGRESS, DEPLOYMENT/MAIL_DNS и эта карточка.
Новых зависимостей/кода приложения нет. Следующие задачи не начинаются.

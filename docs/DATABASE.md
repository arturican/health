# Серверные данные: анализ и реализация

Анализ T159, 15 октября 2026. Архитектура и требования изоляции —
[SERVER_STORAGE.md](SERVER_STORAGE.md). Это спецификация, не утверждение
о готовности перечисленных таблиц/API. Выполнение отражается в [TASKS.md](../TASKS.md).

## Что уже работает

React 19 / TypeScript 6 / Vite 8, Zod, Dexie 4. Восемь разделов имеют формы,
изменение/удаление, состояния отсутствия данных, графики и browser/E2E-тесты.
Все данные пока в 13 таблицах IndexedDB. localStorage/sessionStorage для
дневника не используются. Каталог содержит два явно загружаемых учебных примера;
остальные данные пользователь вводит сам. Макеты design/desktop не являются
источником данных приложения. Fastify 5 имеет только health и безопасные ошибки;
T132 добавляет процесс и сборку, но ещё не авторизацию или данные.

useLiveQuery используется в страницах, сводках и просмотре вложений.
TodayPage, ActivitySummary, EnergySummary, MacroCharts и ActivityOverview
напрямую используют Dexie-транзакции. Их нужно переводить вместе с репозиториями.
ИМТ, калории порций, БЖУ, недельные шаги, баланс и графики вычисляются из исходных
записей. Новые таблицы для каждой карточки или диаграммы не нужны.

## Сущности и ограничения

Первичный источник правил полей — src/domain; API повторно валидирует внешний
unknown. Числа — numeric без фиксированного scale, дни — date, моменты —
timestamptz. NULL означает отсутствие сведений, а не ноль. UUID принадлежит
аккаунту; составные внешние ключи включают user_id. На даты списков нужны индексы
(user_id, date), для версий плана — (user_id, effective_from, revision).

| Таблица | Данные и правила |
|---|---|
| users | UUID, нормализованный уникальный логин, Argon2id hash, IANA timezone; пароль/хеш не экспортируются |
| sessions | Хеш случайного токена, владелец, сроки, CSRF; отзыв на logout, каскад при удалении аккаунта |
| profiles | Один на аккаунт; name ≤80, height_cm >0 и ≤300, birth_date nullable, formula_sex none/male/female |
| weights | UUID; kg >0 и ≤600; один день на аккаунт; не раньше рождения и не в будущем; профиль обязателен |
| products | UUID, name 1–120, source ≤160, kcal 0–10000; БЖУ nullable 0–100 на 100 г; archived |
| food_entries | UUID, date, meal, nullable product_id, независимый снимок названия/источника/состава, grams >0 ≤100000, note ≤500 |
| nutrition_days | (user_id, date), complete; отсутствие строки не означает полный пустой день |
| steps | (user_id, date), целое count 0–1000000 |
| workouts | UUID, date, kind 1–80, minutes >0 ≤1440, kcal nullable 0–100000, source ≤160, note ≤500 |
| energy_plans | UUID, effective_from, created_on, уникальная revision аккаунта, goal_kcal nullable, method none/manual/factor, согласованные параметры; снимок веса/роста/возраста/параметра формулы и даты веса |
| settings | Один на аккаунт; version=1, show_photos/show_documents; скрытие не ограничивает доступ |
| files | UUID, purpose photo/document, MIME, размер и bytea; совпадение размера с байтами, лимит 100 MiB/аккаунт |
| photos | UUID, date, title 1–120, note ≤500, уникальный file_id с purpose=photo, размеры 1–2048 |
| documents | UUID, date, title 1–160, kind lab/report/imaging/other, note ≤500, уникальный file_id с purpose=document |
| lab_results | UUID, document_id, date, name 1–120, числовое значение с оператором либо текст 1–120; unit ≤40, reference ≤160, note ≤500 |

Порция сохраняет снимок после изменения/архивации каталога. Удаление продукта
не должно уничтожать историю питания. Удаление документа каскадно удаляет
показатели; файл и родитель удаляются в одной транзакции. Один файл не разделяется
между фото и документом. Удаление аккаунта каскадно удаляет активные данные.
Видимость и служебные маркеры IndexedDB не превращаются в общую KV-таблицу
медицинских данных. Копии совместимы с прежним форматом, импорт проверяет связи.

## PostgreSQL и VPS

Выбор PostgreSQL уже принят в T129 и подтверждён обследованием. На 2.26.54.81
есть PostgreSQL 18.3, контейнер remnawave-db, постоянный volume,
restart=always, host binding 127.0.0.1:6767. В существующей БД postgres работает
другое приложение. Для дневника создаётся отдельная БД и собственные роли;
runtime не владеет схемой и не имеет SUPERUSER/BYPASSRLS/CREATEDB/CREATEROLE.
Не меняем пользователей, таблицы, volumes и сервисы другого приложения.
Перед изменениями общего кластера нужна закрытая резервная копия.

На сервере данных 3.8 GiB RAM, около 46 GiB свободного диска; заняты
3000/3001/3010/6767, 443 и VPN-порты. На frontend VPS 159.194.208.200 —
1.9 GiB RAM, около 8.5 GiB свободного диска, Nginx и VPN-сервисы.
Frontend лежит в /var/www/health; существующая доставка ставит только dist.
API размещается отдельно, на свободном loopback-порту; Nginx frontend проксирует
/api через проверяемый TLS либо ограниченный SSH-туннель. Публичный 5432 не нужен.
Ресурсы измерены при обследовании и могут меняться.

Для простых SQL-операций достаточно pg и версионированных SQL-миграций:
checksum, транзакция, advisory lock, отдельная роль. ORM не добавляет нужной
функции поверх существующих Zod DTO. Источники:
[параметризованные запросы](https://node-postgres.com/features/queries),
[транзакции на одном соединении](https://node-postgres.com/features/transactions),
[RLS PostgreSQL](https://www.postgresql.org/docs/18/ddl-rowsecurity.html).

## Демонстрация и выпуск

Seed создаёт один явно вымышленный аккаунт, профиль и 90 дней согласованных
наблюдений: вес, питание, пропуски/полнота, шаги, тренировки и версии плана.
Фото — геометрические изображения, документы — синтетические бланки с ручными
результатами (число/оператор/текст). Никаких реальных пациентов или фото людей.
Повтор не дублирует записи и не меняет пароль существующего аккаунта.
Пароль вводится административно через закрытый файл/окружение, а не хранится в Git.
Значения демонстрации не являются медицинскими рекомендациями или порогами.

Переключение frontend выполняется после готовности всех путей данных и проверок
двух аккаунтов. Дизайн, формы, точность и исходные файлы сохраняются.
Резервирование включает проверку восстановления синтетических данных и сохранения
после перезапуска. Реальные данные серверов не выгружаются в инструменты AI.

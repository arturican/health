# Тестирование

## Обязательные проверки

До появления кода, для T000: `node scripts/check-docs.mjs` и `git diff --check`.
После T001 используются следующие команды:

| Команда | Назначение |
|---|---|
| `npm ci` | Воспроизводимая установка по lock-файлу |
| `npm run check:docs` | Существование локальных Markdown-ссылок |
| `npm run typecheck` | Строгая проверка TypeScript приложения, конфигурации и тестов |
| `npm test` | Vitest, один прогон без watch |
| `npm run test:watch` | Vitest в режиме разработки |
| `npm run build` | Production-сборка |
| `npm run test:e2e` | Playwright против предварительно собранного приложения |
| `npm run check` | Все проверки выше, кроме установки и watch |

`test:e2e` требует актуальную сборку: сначала `npm run build`. Полный `check`
делает это сам. `npm run lint` выполняет ESLint с проверкой типов, hooks и доступности JSX.

## Окружение

Используй Node из `.nvmrc`, npm и Chromium для Playwright:

```bash
npm ci
npx playwright install chromium
npm run check
```

На минимальной Linux-системе системные библиотеки браузера устанавливаются
администратором или через `npx playwright install --with-deps chromium`, если
окружение допускает это. В управляемом окружении с уже установленным Chromium:

```bash
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run check
```

По умолчанию Playwright использует свою версию Chromium. Системный браузер —
явный выбор для конкретного окружения; его совместимость подтверждается прогоном.
Тестовый сервер использует `127.0.0.1:4173`, порт должен быть свободен. Старый
процесс приложения не переиспользуется. Отчёты и traces исключены из Git.

## Что тестировать

- Чистые функции: обычный случай, границы, отсутствие значения, неверный ввод.
- Компоненты: доступные роли и подписи, ввод, действие, результат и ошибка.
- Хранилище: транзакции, повторные операции, удаление и восстановление; отдельная
  база для каждого теста, без доступа к пользовательской базе.
- E2E: важный пользовательский путь в реальном браузере. На T001 — загрузка
  production-экрана, переход по ссылке с клавиатуры и мобильная ширина.

Не создавай бизнес-функции ради unit-тестов оболочки. Первые тесты T001 проверяют
экран; unit-тесты появятся вместе с чистыми функциями. Планы граничных сценариев
собраны в [TEST_CASES.md](TEST_CASES.md).

## Правила

Только синтетические данные. Тесты не зависят друг от друга или порядка запуска.
После каждого компонентного теста очищается DOM. Время и случайность явно
фиксируются, если влияют на результат. Сеть заменяется контролируемыми ответами;
реальные внешние сервисы не вызываются.

Используй `getByRole`, `getByLabelText`, `findByRole` и ожидаемые пользователем
результаты. Не проверяй внутренний state, имена CSS-классов или большие snapshots.
Ожидай состояние через assertions, не через произвольные задержки.

Регрессия начинается с воспроизводящего теста. Не используй `.only`,
`passWithNoTests` и необъяснённый `.skip`. Покрытие само по себе не доказывает
качество. Контроль покрытия T003: `npm run test:coverage` проверяет весь src,
кроме тестов и точки запуска main.tsx (её проверяет E2E). Пороги: 80% строк,
инструкций и функций, 70% ветвей; исходная оболочка покрыта на 100%. Новые файлы
включаются даже без импорта тестами. HTML-отчёт — coverage/index.html.
Не ослабляй проверки ради зелёного
результата. Если тест нельзя выполнить, укажи причину и фактически пройденные команды.

Небольшие изменения текста или оформления могут проверяться вручную без нового
автотеста. Правки логики, хранения, импорта и вычислений требуют подходящих тестов.

## Ручная проверка

Axe проверяет компонент в настоящем браузере со стилями, включая применимые
правила контраста и доступных имён. Отдельный отрицательный тест подтверждает,
что кнопка без имени обнаруживается. Axe не заменяет проверку клавиатуры,
содержательности подписей и screen reader.

Перед завершением UI-задачи проверь узкий экран, клавиатуру, читаемость, пустое
состояние и отсутствие ошибок в консоли. Браузерные тесты Chromium не подтверждают
совместимость Firefox/Safari или полноценную доступность: эти проверки расширяются
в будущих задачах. Ручной smoke не заменяет обязательные автоматические проверки.

## Тесты прямо в браузере

`npm run test:browser` открывает Vitest UI с тестами компонентов в Chromium.
Открой адрес runner из терминала: можно выбирать и перезапускать сценарии.
`npm run test:browser:run` — тот же набор в headless-режиме для quality gates.
`npm run build`, затем `npm run test:e2e:ui` — Playwright UI: запуск сценариев,
просмотр реальных кликов и timeline. Эти инструменты доступны только разработчику
и не входят в production-приложение. На WSL при отсутствии дисплея используй
headless-команду; интерфейс runner открывается по напечатанному локальному адресу.

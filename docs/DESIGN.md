# Визуальный стиль

Интерфейс использует светлые поверхности и привычные приёмы Telegram / Google
Material: синие действия, спокойный фон, круглые кнопки, ясный активный раздел,
единые пиктограммы и адаптивную сетку. Это собственное приложение, без логотипов
или заявления о связи с этими сервисами.

## Пиктограммы

Material Symbols Rounded от Google LLC, Apache-2.0. SVG-пути скопированы из
[официального репозитория](https://github.com/google/material-design-icons/tree/master/symbols/web)
в [Icon.tsx](../src/ui/Icon.tsx), без изменения геометрии. Используются home,
person, monitor_weight, restaurant, directions_walk, photo_library, description,
settings и monitor_heart в варианте materialsymbolsrounded, 24 px.
[Лицензия](../licenses/material-symbols-LICENSE.txt) включена в репозиторий.
Иконки локальны, не загружают шрифты/скрипты; названия действий остаются текстовыми.

## График и показатели

График веса использует синюю линию, мягкую заливку, координатную сетку и круглые
маркеры фиксированного экранного размера. Даты и границы шкалы отображаются
обычным текстом, который не уменьшается вместе с SVG на телефоне. Интервалы
соответствуют календарю, линия соединяет только настоящие измерения без сплайна.

Касание/клик выбирает ближайшую по дате точку. Стрелки, Home/End и список дат
дают тот же выбор с клавиатуры. Над графиком показываются точные значение и дата;
правка/удаление не оставляют устаревшие показатели. Доступная история и пояснение
адаптированной шкалы сохранены. Индикатор питания остаётся нативным meter,
оформленным в той же синей палитре. Цвет не оценивает состояние здоровья.

## Подготовка нового Figma-проекта

Запрос от 15 октября 2026 года: создать дизайн с нуля; существующего Design-файла
нет. Сейчас разрешён только подготовительный этап T076. Подробная очередь —
в [TASKS.md](../TASKS.md); после каждого этапа показать результат и ждать
подтверждения. Frontend начинается после утверждения соответствующего макета.

### Фактически проверенное подключение

- Среда: Codex desktop app с облачным Linux-workspace `/workspace/health`.
- Поиск каталога обнаружил плагин Figma, доступный для установки, `installed=false`.
  Его описание заявляет передачу экранов в редактируемые слои; это описание
  возможностей, а не проверка инструментов текущего сеанса.
- Среди доступных инструментов сеанса Figma отсутствует. Создание нового файла,
  нативных узлов, Variables, Styles, Components, Auto Layout и права редактора
  пока не проверены. Ссылка на созданный файл появится после фактического создания.
- Read-only `codex mcp list --json` показал 0 локально настроенных серверов;
  конфигурация не дублировалась и не изменялась. CLI в облаке поддерживает
  `codex mcp add --url` и `codex mcp login`, что проверено через `--help`.
- Прямой GET к `https://mcp.figma.com/mcp` из облака отклонён сетевым прокси:
  `Tunnel connection failed: 403 Forbidden`. Это ограничение маршрута из облака,
  а не доказательство отказа сервера Figma или отсутствия прав у пользователя.

В desktop app сначала установить Figma через интерфейс плагинов и лично пройти
OAuth. Не передавать токены/пароли в чат или репозиторий. После подключения
проверить доступные инструменты и создание нового Design-файла «Дневник здоровья»
в доступном пользователю пространстве; проверить права на фактическом файле.
Успешная авторизация сама по себе не доказывает возможность нативной записи.

Альтернатива для пользователя, работающего именно в Codex CLI: сначала проверить
`codex mcp list`, затем при отсутствии сервера с таким URL выполнить на своём хосте:

```bash
codex mcp add figma --url https://mcp.figma.com/mcp
codex mcp login figma
```

OAuth выполняет пользователь самостоятельно. Эти команды не запускались в
облачной конфигурации: основной клиент этой задачи — desktop app. Не настраивать
одновременно два подключения без необходимости. Точный состав инструментов
и доступность записи проверяются после подключения; при read-only доступе
сообщить ограничение и не заменять нативные элементы статическими изображениями.

### Границы и структура макетов

Первый экран — главная панель: сначала Desktop 1440 px, затем Mobile 390 px,
затем пустой дневник и частичные данные. Основа визуального направления —
светлая тема, ясная типографика, синий акцент с бирюзовым/зелёным дополнением.
Цвет не передаёт медицинскую оценку; тёмная тема остаётся будущей идеей.
Макеты должны быть оригинальными, без копирования чужого интерфейса целиком.

Будущие страницы файла: Foundations, Icons, Components, Charts, Desktop Screens,
Mobile Screens, Prototypes. Создавать их и наполнять после проверки нативных
операций, в рамках выбранной маленькой задачи. Текущая подготовка их не создаёт.

Текущий MVP описан в [MVP.md](MVP.md). Вода, сон, АД, пульс, глюкоза, подходы/
повторения и привычки — концепции будущего дизайна, а не уже работающие функции.
См. [IDEAS.md](../IDEAS.md), в том числе I003, I005, I018 и I021–I023.
Для демонстрации использовать синтетические данные с явной отметкой «Демо»;
неизвестное не заменять нулём, единицы и сопоставимость рядов проверять отдельно.

### Токены и передача в код

Исходные ориентиры существующего кода — [styles.css](../src/styles.css):
primary `--accent`, text `--ink`/`--muted`, surface `--surface`, border `--line`,
shadow `--shadow`. Фон, шрифты, отступы и часть радиусов пока заданы напрямую;
полной системы Variables в Figma ещё нет. Эти значения служат инвентаризацией,
не окончательным решением нового дизайна.

Будущие Foundations охватывают colors (primary/secondary/surface/background/text/
border/semantic), typography, spacing, radius, shadows, icon sizes и states.
При поддержке инструмента использовать Variables/Styles, Components/Variants
и Auto Layout. Фиксировать соответствие Figma-имени и CSS-переменной, состояние,
единицу и роль токена; ограничения неподдерживаемых операций записывать явно.

Переиспользовать текущие типизированные компоненты и SVG там, где это подходит
утверждённым макетам. Библиотека графиков или другая зависимость требует отдельного
обоснования. Дизайн-концепция не меняет схемы/формулы/историю данных автоматически.
Векторные иконки остаются редактируемыми и экспортируемыми в SVG; графики —
редактируемыми компонентами с легендой/подписями, доступными без различения цвета.

### Проверки будущих этапов

Для Figma: ссылка на конкретный frame/node, понятные имена слоёв и вариантов,
редактируемые текст/вектор, переиспользование компонентов, Auto Layout при
поддержке, читаемость и WCAG AA-контраст, явные единицы, пустые состояния.
Скриншот служит превью, а редактируемость проверяется отдельно на узлах файла.
Изменения только в Figma отмечаются отдельно, без выдуманного Git-коммита.

Для кода сохраняются [TESTING.md](TESTING.md) и существующие unit, Native Browser,
Playwright, axe, responsive и design-тесты. Утверждённый визуальный diff просмотреть
до точечного обновления эталонов; допуски не ослаблять. Для подготовки меняется
только документация: `npm run check:docs` и `git diff --check`.

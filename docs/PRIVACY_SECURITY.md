# Приватность и ограничения

В разработке, тестах, скриншотах, логах и репозитории используются только
синтетические данные. Реальные медицинские документы и фотографии людей
не загружаются в Codex или внешние AI-сервисы.

## Хранение и сеть

Дневник и вложения хранятся в PostgreSQL на VPS 2.26.54.81. Браузер обращается
к API через HTTPS dev.arturican.com; Nginx на 159.194.208.200 передаёт запросы
по закрытому SSH-туннелю. Оба сервера входят в границы обработки данных.
API/БД слушают loopback. Рабочая база не имеет прикладного шифрования at rest;
администратор VPS/СУБД может получить доступ. Это не сквозное шифрование.

Вход — подтверждённая почта/пароль, для прежних аккаунтов сохранён логин;
Argon2id с солью, cookie Secure/HttpOnly/SameSite=Lax.
Сервер проверяет сессию, Origin/CSRF, владельца и ревизии. Личные таблицы
дополнительно защищены FORCE RLS. Runtime-роль не владеет схемой и не обходит RLS.
Регистрация email-first: адрес/часовой пояс, затем пароль 15–1024 символа по
одноразовой ссылке; до подтверждения вход невозможен. Старый маршрут регистрации
по логину закрыт. Email сравнивается без регистра, локальная часть сохраняется
для доставки; точки/+tag не удаляются. Поддерживается ASCII dot-atom и punycode.
Старые аккаунты привязывают почту в настройках после текущего пароля и письма.
Адрес принадлежит одному аккаунту, автоматического объединения/замены почты нет.

Подтверждение действует час, сброс — 15 минут. В БД SHA-256 случайного
256-битного секрета, ссылки заменяются при повторной выдаче не чаще минуты.
Погашение атомарное/одноразовое; меняет пароль, отзывает все сессии и остальные
ссылки, очищает текущую cookie, требует обычного входа. Секрет во fragment
удаляется из history при открытии, не хранится в storage и не уходит в referrer.
Вход повторно сверяет хеш под той же блокировкой, что сброс, до записи сессии.

Публичные запросы писем отвечают одинаково для разных состояний адреса;
ошибки SMTP не раскрываются. В памяти: выдача 30/min/IP и 5/15min/email,
погашение 10/15min/IP; привязка 30/min/IP и 5/15min/account. Максимум четыре
одновременных хеширования вместе со входом. Лимит входа: 5/15 минут на
почту/логин, 30/min/IP. За proxy IP общий, после рестарта память сбрасывается;
минутный интервал выдачи дополнительно хранится в БД. Совместного доступа нет.

Служебные письма проходят локальные Postfix/OpenDKIM, затем почтового провайдера
получателя. Они содержат только адрес и ссылку, без записей/вложений дневника.
В SMTP-очереди письмо временно содержит исходную ссылку; администратор VPS
и почтовый провайдер могут прочитать её. Журналы SMTP/API не содержат адресов
и токенов. Подробнее — [MAIL_DNS.md](MAIL_DNS.md).

Текущие данные находятся только в памяти вкладки, не в localStorage/IndexedDB.
Сессия переживает reload благодаря cookie; выход отменяет запросы и очищает
состояние вкладок. Ответы API и файлов имеют no-store; статика кешируется.
Нужен доступный backend: offline/PWA/очередь изменений не реализованы.
Прежняя IndexedDB сохраняется отдельно; её чтение для экспорта выполняется
только по кнопке. Автоматической отправки или удаления прежних записей нет.

Внешней аналитики, удалённых шрифтов и AI нет. Справочные ссылки открываются
только пользователем. Защищённые файлы показываются через временные object URL;
публичных ссылок нет. Скрытие раздела — настройка UI, данные остаются в аккаунте
и входят в полную копию. VITE_* публичны; секреты находятся в закрытых серверных
env вне репозитория. API не пишет тела/пароли/cookie, Nginx не журналирует API.
Для ролей дневника отключено журналирование SQL/параметров и обычных SQL-ошибок;
точные настройки и ограничения диагностики — [DEPLOYMENT.md](DEPLOYMENT.md).

## Фото и документы

Фото принимаются в JPEG, PNG или WebP размером до 10 MiB. Проверяются тип,
контейнер и декодирование изображения; предел исходного изображения — 64 млн
пикселей и 32768 px по каждой стороне. Интерфейс перед отправкой через canvas создаёт новый
JPEG с параметром качества 0.9, без EXIF, с сохранением пропорций и максимум
2048 px по большей стороне. Маленькие фото не увеличиваются, прозрачный фон
становится белым. Исходный файл фото не сохраняется. API повторно проверяет байты, JPEG,
размеры и декодирование; не следует считать его универсальным анонимизатором метаданных.

Документы принимаются в PDF, JPEG, PNG или WebP до 20 MiB. Сохраняются исходные
байты, включая имеющиеся метаданные. Изображения проходят проверку размеров
и декодирования с теми же пределами 64 млн пикселей и 32768 px. Проверка MIME,
сигнатуры и границ контейнера не является полной проверкой PDF или поиском
вредоносного содержимого. PDF не встраивается в страницу: доступно скачивание
оригинала; изображения можно просматривать. Общий лимит вложений — 100 MiB.
Здесь 1 MiB = 1024 × 1024 байта; общий предел применяется на аккаунт.

## Резервные копии и удаление

Текстовая JSON-копия до 20 MiB содержит профиль, вес, продукты, записи еды,
отметки полноты питания, шаги, тренировки и калорийные планы. Её восстановление
заменяет эти данные одной транзакцией, сохраняя фото, документы, ручные показатели
и настройки видимости. Файлы и показатели в текстовую копию не входят.

Полная JSON-копия до 200 MiB включает 13 областей пользовательских данных: перечисленные данные,
файлы, фото, документы, ручные показатели и метаданные с настройками видимости.
Сначала проверяются JSON-схемы, связи записей, лимиты, Base64 и содержимое файлов,
затем показывается состав копии. Восстановление требует явного согласия в UI,
повторяет проверку и заменяет данные владельца одной серверной транзакцией. Пустые разделы копии
также заменяют соответствующие данные; при ошибке транзакция откатывается.
Полная копия содержит скрытые разделы и оригиналы документов. Оба вида копий
не зашифрованы.

Удаление дневника требует явного подтверждения текущей версии. Личные записи
и файлы очищаются транзакционно, аккаунт и сессия остаются; UI сбрасывает
черновики и предпросмотры. Новая generation отменяет отложенные операции старого
дневника. Чужой аккаунт не затрагивается. Устаревшее подтверждение даёт конфликт.

Скачанные JSON и исходники на устройстве остаются у владельца. Удаление из
PostgreSQL не обещает физического стирания носителя и не удаляет старые резервные
копии немедленно. Серверные GPG-копии отличаются от незашифрованного JSON:
7 последних на data VPS, 14 на frontend VPS; cluster baseline хранится отдельно.
Приватный recovery key только локально, вне VPS/Git. При восстановлении старого
архива могут вернуться удалённые записи и сессии; восстановленные сессии нужно
отозвать. Фактическое восстановление синтетической БД проверено; порядок и
хранение ключа — [BACKUPS.md](BACKUPS.md). Автоматических внешних оповещений нет.

## Медицинские границы

Фото служат для сравнения по датам, без определения диагноза, степени ожирения
или процента жира. ИМТ — справочная категория для взрослых с указанными в UI
ограничениями, не диагноз. Показатели документов вводятся вручную, без OCR,
AI, автоматической медицинской интерпретации или прогноза.

Калорийная цель задаётся пользователем и не является назначением. Оценка расхода
и калорийная цель — разные величины; расход по коэффициенту активности не
складывается с расходом тех же шагов и тренировок. Отсутствие данных не считается
нулём, а значения веса и баланса не оценивают ценность человека. Ограничения
расчётов описаны в [CALCULATIONS.md](CALCULATIONS.md).

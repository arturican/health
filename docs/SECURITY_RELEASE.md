## Порядок внедрения и отката T205

После отдельного разрешения, без автоматического выполнения этих пунктов:

1. Приватно проверить целевые роли/loopback/tunnel и действующую конфигурацию.
   Глобальные real_ip-настройки Nginx не должны доверять произвольному клиенту;
   если впереди есть CDN/другой proxy, сначала пересмотреть границу T200.
2. Создать штатную GPG-копию и сверить внешнюю передачу/SHA/возможность
   восстановления. Сохранить предыдущие API/edge/env и перечень версий миграций.
   Не выводить секреты/данные; подключение через закрытые env/pgpass, не CLI-пароль.
3. Применить только новую 015 миграцию migration-ролью. Проверить функции/ACL:
   runtime EXECUTE разрешён, прямой доступ к auth_rate_limits запрещён.
4. Доставить Nginx-конфигурацию только целевого virtual host, выполнить nginx -t.
   Сначала включить замену forwarded и CSP на edge. Проверить HTTP/HTTPS,
   статику/ошибки и заголовки без доступа к реальным записям.
5. Доставить API с постоянными лимитами. После проверки edge задать
   API_TRUST_PROXY=true в закрытом env и перезапустить только health-api.
   Публичные порты API/БД не открывать, пересылку доверять только loopback hop=0.
6. Создать/использовать только отдельные синтетические аккаунты для smoke:
   вход/выход, чужие ID, фото/PDF/копии, CSP без ошибок, разные исходные IP.
   Не исчерпывать бюджеты реальных пользователей. Проверку лимита после
   перезапуска планировать контролируемо вместе с проверкой обычного входа.
7. Сверить release/artifact, health и новые права; проверить, что отсутствуют
   тестовые маршруты и лишние сетевые обращения. Записать результат отдельно
   от локальных тестов. SMTP-доставка требует отдельной синтетической проверки.

Откат: сначала выключить API_TRUST_PROXY, затем вернуть предыдущий API;
при необходимости вернуть edge/env после nginx -t. Таблицу/функцию 015 оставить:
предыдущий API её не использует, удаление не нужно. Не сбрасывать лимиты
автоматически и не восстанавливать старую БД ради отката кода.
Если восстановление БД необходимо, использовать новую изолированную БД,
актуальные миграции и SQL T203 по [BACKUPS](BACKUPS.md). Не выполнять --clean
поверх рабочей БД. Сессии/ссылки после аварийного восстановления отозвать;
актуальность паролей и возврат удалённых данных проверить до открытия API.

## Оставшиеся решения и критерии отдельных работ

| Область | Текущая защита и предел | Конкретное следующее решение |
|---|---|---|
| PDF | Исходные байты, квоты, авторизация, attachment/nosniff/sandbox; встраивания нет. Это не проверка на вредоносное содержимое | Если нужен антивирус/CDR, выбрать локальную обработку без отправки документов, политику отказа/тайм-аутов и сохранения оригинала. Проверить безопасные/повреждённые/пограничные образцы и работу при отказе сканера |
| Рабочая БД | RLS, ограниченные роли, loopback/tunnel и HTTPS; прикладного шифрования нет | Сначала определить угрозу: кража выключенного носителя или администратор работающего сервера. Для первого рассмотреть шифрованный volume с отдельным планом ключей/старта/восстановления; для второго требуется клиентское шифрование и изменение серверных функций |
| JSON-копии | Совместимый незашифрованный экспорт; пользователь сам хранит скачанный файл | До изменения формата выбрать пароль/ключ и восстановление при потере. Критерии: неверный пароль/повреждение не меняют дневник, старый JSON импортируется, ключ не хранится на сервере. Сейчас использовать защищённое хранилище устройства или отдельную локальную упаковку |
| Recovery key | Приватный ключ вне VPS/Git, права 0700/0600; существующий ключ без passphrase | Отдельно подготовить защищённую офлайн-копию/защиту устройства и проверить восстановление до ротации. Не уничтожать прежний ключ: старые архивы должны оставаться восстанавливаемыми. Приватный материал не передавать AI |
| Retention | 7 локальных/14 внешних копий по количеству, cluster baseline отдельно; удаление дневника не стирает все старые архивы | Согласовать срок/объём хранения, судьбу baseline и допустимость восстановления удалённых данных. Затем проверить обе стороны, сбой передачи, предел места и восстановление до изменения/удаления архивов |

Эти границы нельзя устранить одной настройкой: шифрование смонтированного
volume не защищает от администратора с доступом к работающей системе.
Новая политика ключей, формата или удаления копий не выбиралась молча.

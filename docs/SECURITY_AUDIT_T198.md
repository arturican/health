общий слот импорта/экспорта. Следующие запросы получали 429 до перезапуска процесса.

## Потенциальные риски и рекомендации

- **Доступность за общим proxy IP.** createApi не доверяет forwarded-заголовкам;
  Nginx передаёт запросы через общий tunnel. createLoginLimit/createRegistrationLimit
  поэтому делят IP-бюджет между пользователями, в том числе погашение ссылок
  10/15 минут. Клиент может исчерпать общий бюджет. Это известное ограничение
  развёртывания, а не обход доступа. Отдельная задача: лимиты на Nginx по исходному
  адресу и согласованная передача адреса через доверенный proxy; нельзя просто
  включить trustProxy для произвольных заголовков. Память лимитов также
  сбрасывается при рестарте.
- **Привилегированный доступ к данным.** Рабочая БД без прикладного шифрования,
  администраторы БД/VPS и почтовый провайдер видят доступные им данные/ссылки.
  Это описанные границы доверия, не новая уязвимость. Шифрование/политика
  хранения требуют отдельного решения; старые копии могут вернуть удалённые данные.
- **PDF остаются исходными файлами.** Проверка контейнера не антивирус и не
  обезвреживание активного содержимого. Они скачиваются, а не встраиваются
  в приложение; пользовательский просмотрщик — за пределами аудита.
- **Усиление защиты страницы.** Для HTML в nginx нет Content-Security-Policy.
  XSS не воспроизведён; CSP — дополнительная защита. Отдельно подготовить
  совместимую политику с локальными blob-preview и проверить её в браузере;
  не менять production-заголовки без этой проверки.

# Desktop-макеты дневника

Это архив концептов T136–T144, а не описание текущего runtime. На 20.10.2026
в приложении уже работают серверное хранение, графики БЖУ и графики вручную
введённых показателей (T145–T158 и последующий API-переход). Фразы ниже и в
шаблонах о будущем подключении графиков/хранении в браузере относятся к моменту
создания макетов. OCR, распознавание и сверка фрагментов остаются предложением.
Фактическое устройство — [ARCHITECTURE](../../docs/ARCHITECTURE.md).

Локальные концепты 1440 px по одобренному экрану «Сегодня» и предоставленному
SVG-референсу. Это статичные макеты, а не работающие формы приложения.
Откройте [галерею](index.html): рядом с каждым разделом доступны SVG и PNG,
а также отдельный лист редакторов и состояний.

## Использование

В разделе документов (T144) теперь показан будущий сценарий только для анализов:
загрузка → распознавание → сверка с бланком → подтверждение → график.
На график попадают подтверждённые сопоставимые значения по дате забора образца.
Исходный фрагмент и исправляемые поля показаны рядом. Изменение значения
описывается нейтрально; медицинские нормы и оценки «лучше/хуже» не добавлены.
В приложении этот сценарий пока не реализован: распознавание, просмотр фрагментов,
подтверждение и графики требуют отдельной задачи. Способ обработки файлов не выбран,
в этом макете нет подключения к OCR/AI и отправки документов. Название пункта
«Документы» в общей навигации сохранено для связи с остальными экранами.

В питании (T143) добавлены пиктограммы БЖУ и графики по приёмам пищи.
Дневные итоги, подписи записей и длины полос строятся из одного синтетического
набора порций в nutrition.cjs. Шкала 0–80 г подходит для этого примера и не
обозначает норму. В приложении диапазон должен вмещать фактические значения.
Источник будущего подключения — сохранённые снимки продуктов и масса порций
выбранного дня, существующие portion / foodTotals; подключение пока не выполнено.
Лист состояний различает неизвестное БЖУ, пустой неполный день и известный ноль.

Перетащите SVG на существующую страницу Design в Figma Starter.
Импорт не создаёт Auto Layout, Variables и связанные компоненты автоматически;
сохранение текста после импорта в Figma здесь не проверено.
Шрифт — приложенный Roboto; [лицензия шрифта](Roboto-LICENSE.txt).
Иконки взяты из приложения; [лицензия иконок](material-symbols-LICENSE.txt).
Все данные синтетические; в фото используются только геометрические заглушки.

Для воспроизведения из корня репозитория: `node design/desktop/render.cjs nutrition`
(замените имя на нужный модуль). Используется уже установленный Playwright;
новых зависимостей нет. Генератор создаёт SVG, PNG, отчёт проверок и галерею.
В минимальном WSL Chromium требует доступных системных библиотек;
настройки окружения не являются частью макетов.

Утверждённая главная сохранена как визуальная основа. T133 остаётся blocked
для нативной Figma-композиции; локальная очередь T136–T142 разрешена отдельно.
Адаптивность, Mobile и реализация frontend не входят в эту очередь.

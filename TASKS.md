# Очередь маленьких задач

**Текущее состояние:** пользователь разрешил полную реализацию T002–T062 в dev с браузерными тестами и отдельным коммитом каждого шага. T000/T001 завершены. Ближайшая задача — **T050b**.

**Правило:** один ID → один небольшой результат → проверки → один локальный коммит. После явно согласованных этапов — остановка. Нельзя реализовывать этап целиком. Правила размера и Git — в [AGENTS.md](AGENTS.md) и [WORKFLOW.md](docs/WORKFLOW.md).

Это последовательный учебный план T001–T062 и подготовительная T000, не оценка сроков. Карточки ближайших задач существуют; для дальних ID карточка с критериями создаётся перед выбором задачи. Даже внутри одной карточки при превышении бюджета сначала предложить разделение, а не писать большой diff. Количество задач может измениться после согласованного разбиения или review.

Статусы: `todo` — не начато; `in_progress` — только одна задача; `blocked` — есть конкретный блокер; `done` — критерии выполнены и коммит успешно создан; `split` — заменена согласованными подзадачами. Статусы редактируются только здесь, карточки не дублируют их. Hash берётся из Git, не придумывается.

Зависимости намеренно линейные: каждая задача требует предыдущую. Это упрощает пошаговое обучение и не разрешает параллельный автопроход. Просьба «начать проект» или «следующая задача» разрешает только один ближайший доступный ID. Явный запрос полной реализации разрешает последовательную очередь локального MVP, но не IDEAS.

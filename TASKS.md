# Очередь маленьких задач

**Текущее состояние:** код приложения не создан; все задачи ниже `todo`. Начальный пакет документации коммитится отдельно по README. Ближайшая задача после этого — **T001**.

**Правило:** один выбранный ID → один небольшой результат → проверки → один локальный коммит → остановка. Нельзя реализовывать этап целиком. Правила размера и Git — в [AGENTS.md](AGENTS.md) и [WORKFLOW.md](docs/WORKFLOW.md).

Это последовательный учебный план из 62 задач, не оценка сроков. Даже внутри одной карточки при превышении бюджета сначала предложить разделение, а не писать большой diff. Количество задач может измениться после согласованного разбиения или review.

Статусы: `todo` — не начато; `in_progress` — только одна задача; `blocked` — есть конкретный блокер; `done` — критерии выполнены и коммит успешно создан; `split` — заменена согласованными подзадачами. Статусы редактируются только здесь, карточки не дублируют их. Hash берётся из Git, не придумывается.

Зависимости намеренно линейные: каждая задача требует предыдущую. Это упрощает пошаговое обучение и не разрешает параллельный автопроход. Просьба «следующая задача» разрешает только один ближайший доступный ID.

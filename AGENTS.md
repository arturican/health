# Health Diary — правила для Codex

Личный дневник: React/TypeScript/Vite → Fastify → PostgreSQL.
UI по-русски, идентификаторы по-английски. AI и совместного доступа нет.

## Архитектура

- main → AuthBoundary → App; pages/ui отображают данные и состояния форм.
- dataAccess экспортирует client: HTTP, сессия, запросы и команды API.
- domain содержит схемы и чистые расчёты; media готовит файлы/копии.
- server/runtime регистрирует Routes; Records работают через транзакции владельца.
- data/legacy — явные тестовые адаптеры и экспорт прежней IndexedDB.
  Рабочие восемь экранов используют только API.
- Точки входа, документы и gates: [PROJECT_MAP](docs/PROJECT_MAP.md).
  Особенности: [UI](src/pages/AGENTS.md), [API](src/server/AGENTS.md).

## Одна задача → проверки → коммит

1. Проверь git status --short --branch, diff, diff --cached, log -5 --oneline.
   Не трогай прежние изменения; при пересечении/чужом staged diff остановись.
2. Читай [WORKFLOW](docs/WORKFLOW.md), карточку docs/tasks/Txxx.md, строку
   [TASKS](TASKS.md) и записи [PROGRESS](docs/PROGRESS.md) по ID через rg.
   Файлы ищи по карте и rg; изучай модуль, вызовы и тесты, расширяя поиск по нужде.
3. До правок назови ID, результат, файлы и проверки. Нет карточки — создай её.
   Одна задача: один наблюдаемый результат, до 5 файлов приложения и до 250
   добавленных/удалённых строк реализации. Тесты/документы/lock и генератор отдельно.
   Превышение сначала разбей на подзадачи; не ужимай код/тесты ради бюджета.
4. Выполни критерии и связанные проверки. Обнови TASKS/PROGRESS тем же коммитом;
   проверь diff --check, staged diff и секреты. done подтверждается коммитом.
   При провале обязательного gate не объявляй задачу завершённой/не деплой.
5. Создай один коммит задачи. При согласованной очереди продолжай последовательно
   до её выполнения; после согласованного объёма остановись. «Следующая» разрешает
   только одну доступную задачу. [IDEAS](IDEAS.md) не разрешает реализацию.
   Не запускай фоновые проходы backlog или параллельных агентов для других задач;
   делегировать review текущей задачи можно.

## Git и окружение

- Добавляй только явные пути; без add ., add -A, commit -a, auto-stash,
  reset/clean/restore поверх чужих правок. Сообщение: type(scope): Txxx действие.
- Push/деплой требуют явного разрешения; оно действует на согласованную очередь.
  PR/merge/rebase/amend/force push/удаление веток и перезапись истории не разрешены
  обычной задачей. Не меняй глобальный Git/автора, модель, настройки безопасности
  агента или подключения. После коммита сообщи фактический hash.
- WSL/Linux: source ~/.nvm/nvm.sh; nvm use. Версии: .nvmrc/package.json.
  npm ci — при первой установке/изменении lock, не перед каждой задачей.
  В PowerShell запускай команды через WSL в /home/artur/health.
- UI: npm run dev; API: npm run dev:api. БД/роли/env — [README](README.md).
  Между этапами — связанные тесты; перед push после последних изменений —
  npm run check и build:api, соответствующие deploy gates из карты.
  Только документы: check:docs + diff --check. Не повторяй успешные неизменённые
  проверки; полный лог сохраняй вне Git, показывай итог/ошибки.
- Штатная доставка: push dev → CI check/deploy frontend; API отдельным артефактом,
  свежая внешняя копия, SHA256, атомарный current/откат:
  [DEPLOYMENT](docs/DEPLOYMENT.md), [BACKUPS](docs/BACKUPS.md).
  Готовность релиза: точный SHA, успешный CI, live browser/API, сохранность данных.
- Блокер сначала безопасно исправляй в разрешённых каталогах; не ослабляй gates.
  При несозданном коммите верни done в in_progress/blocked и объясни причину.

## Качество и данные

- [CODING_STANDARDS](docs/CODING_STANDARDS.md): strict, без any/@ts-ignore/
  as unknown as; внешний ввод unknown + runtime-схема, расчёты вне JSX,
  без производных сумм в state и абстракций на будущее.
- [TESTING](docs/TESTING.md): баг начинается с регрессии; обычный случай,
  границы/ошибка/нет данных; роли/подписи/действия, очистка DOM/хранилищ,
  явная дата, без внешней сети, произвольных задержек, only/skip/passWithNoTests.
  Текст/стили допускают ручную проверку; не пиши тесты-копии реализации.
- Только синтетические данные в разработке, тестах, логах, снимках, Git и AI. Секреты,
  реальные анализы/фото людей не загружать в Codex. Без внешней аналитики,
  удалённых шрифтов, отправки документов, frontend-ключей и публичных ссылок.
- Фото — сравнение по датам без диагнозов/степени ожирения/процента жира; ИМТ — справка.
  Нет данных ≠ ноль; цель ≠ расход, без двойного учёта активности.
  Дефицит не «хорошо», избыток не «плохо». До изменения формул читай
  [CALCULATIONS](docs/CALCULATIONS.md), уточняй пороги в задаче, не выдумывай их.
- Данные/auth/файлы: [PRIVACY_SECURITY](docs/PRIVACY_SECURITY.md).
  Локальная БД не гарантирует шифрование/сохранность; клиентская роль не даёт защиты.
  Новые зависимости/интеграции и изменения объёма требуют отдельной карточки.
  Карту/инструкции меняй только вслед за проверенным изменением фактов.

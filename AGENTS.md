# Health Diary — правила для Codex

## Главное: ОДНА задача → проверки → ОДИН коммит → СТОП

- Выполняй только задачу, явно выбранную пользователем из `TASKS.md`. Если пользователь просит «следующую», выбери ровно одну ближайшую незавершённую задачу с выполненными зависимостями.
- Сначала прочитай этот файл, выбранную карточку `docs/tasks/Txxx.md`, `docs/PROGRESS.md` и только относящиеся к задаче спецификации. Не реализовывай весь backlog.
- До изменения файлов напиши кратко: ID, ожидаемый результат, затрагиваемые файлы, проверки. Это сообщение не является просьбой о дополнительном подтверждении уже выбранной задачи.
- Ориентир небольшой задачи: 1 наблюдаемый результат, до 5 вручную изменяемых файлов приложения и до 250 добавленных/удалённых строк реализации. Тесты и краткие обновления документации не входят в этот бюджет, но тоже должны быть небольшими. Lock-файл и неизменённый шаблон генератора считаются отдельно. Эти числа — договорённость проекта, а не универсальный стандарт.
- Если выполнение требует большего объёма, остановись до реализации и предложи подзадачи с отдельными критериями и коммитами. Не ужимай код, не удаляй тесты ради лимита. Исключение допускается только по явному разрешению пользователя.
- Не начинай следующую задачу после коммита. Не запускай параллельных агентов для других задач, фоновый цикл или автопроход по списку. Не коммить несколько задач одним изменением.
- Идеи из `IDEAS.md` НЕ разрешены к реализации. Новая зависимость, рефакторинг вне текущей задачи, сервер, AI, синхронизация и интеграции требуют отдельной задачи.

## Перед работой и Git

Прочитай `docs/WORKFLOW.md`. Проверь `git status --short --branch`, `git diff`, `git diff --cached` и последние коммиты. Не трогай чужие или прежние незакоммиченные изменения; не выполняй auto-stash, reset, clean, checkout/restore поверх них. При пересечении или чужом staged diff остановись с описанием конфликта.

Пользователь разрешает один ЛОКАЛЬНЫЙ коммит для завершённой выбранной задачи. Не выполняй push, PR, merge, rebase, amend, удаление веток или перезапись истории без отдельного разрешения. Не меняй глобальную Git-конфигурацию, личность автора и настройки безопасности Codex.

Добавляй в индекс только явные пути своей задачи; запрещены `git add .`, `git add -A` и `git commit -a`. Перед коммитом проверь staged diff и отсутствие секретов. Сообщение: `type(scope): Txxx краткое действие`, тип `feat`, `fix`, `test`, `refactor`, `docs` или `chore`. ID и рекомендуемое сообщение есть в карточке.

## Готовность и отчёт

- Выполни критерии карточки, тесты изменения и доступные quality gates из `docs/TESTING.md`. Проверь `git diff --check`.
- Не ослабляй тесты, TypeScript, ESLint или проверки импорта, чтобы получить зелёный результат. Не прячь ошибки и не заявляй о проверках, которые не запускались.
- Обнови статус в `TASKS.md` и запись в `docs/PROGRESS.md` тем же коммитом. Собственный hash в коммит не записывай: его покажешь после создания коммита. При неудачном коммите статус не должен оставаться `done`.
- Не коммить как завершённую задачу с не пройденными обязательными проверками. Если окружение мешает проверке/коммиту, оставь задачу `blocked`, сообщи причину и остановись; не выдумывай hash.
- Финальный отчёт: ID; что изменилось; проверки с фактическим результатом; hash и subject созданного коммита или «коммит не создан»; как проверить в интерфейсе; 2–4 предложения, чему учит изменение; одна следующая задача, которую ты НЕ начинаешь.

## Код

Предлагаемый стек: React + TypeScript + Vite; npm; обычный CSS/CSS Modules; IndexedDB через Dexie. Инструменты добавляй только в разрешённой задаче. При первичной установке проверь совместимость стабильных версий по официальной документации, зафиксируй Node и зависимости. Не выбирай версии по памяти.

`strict: true`; никаких `any`, `@ts-ignore` и `as unknown as` как обхода проверки. Внешние данные сначала `unknown`, затем runtime-валидация. Расчёты — чистые функции вне JSX. Не дублируй вычисляемые суммы в React state. Не делай абстракции «на будущее». UI по-русски, идентификаторы по-английски. Подробности: `docs/CODING_STANDARDS.md`.

## Непереговорные ограничения продукта

- Только синтетические данные в разработке, тестах, скриншотах, логах, репозитории и запросах к AI. Не загружать реальные анализы или фотографии людей в Codex.
- Фото — сравнение по датам, НЕ определение диагноза, степени ожирения или процента жира.
- ИМТ — справочная категория с ограничениями, не диагноз. Не оценивать ценность человека по весу.
- Калорийная цель и оценка расхода — разные величины. Не складывать расход по коэффициенту активности с расходом тех же шагов/тренировок. Нет данных ≠ ноль. Дефицит не «хорошо», избыток не «плохо».
- Полная спецификация вычислений: `docs/CALCULATIONS.md`. Не придумывать формулы и медицинские пороги.
- Локальная база не гарантирует шифрование/сохранность. Не добавлять внешнюю аналитику, удалённые шрифты, отправку документов, ключи в frontend или публичные ссылки на вложения. Подробности: `docs/PRIVACY_SECURITY.md`.
- Совместный доступ врача/тренера/друзей отсутствует в локальном MVP. Его нельзя имитировать одной клиентской проверкой роли.
